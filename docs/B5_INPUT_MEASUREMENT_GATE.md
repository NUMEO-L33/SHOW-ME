# B5-B3b3 — 입력 실측 결과와 생성 전송의 연결

갱신일: 2026-09-15 · **로컬 구현·검증 완료, 자동 입력량 조회/운영 분석은 꺼짐**

후속 B5-B3b4에서 계산의 별도 PostgreSQL 원장·공유 예산·정산/복구를 구현하고 총 498개를 검증했다. 실제 계수 실행기/자동 분석은 여전히 미연결이다. [최신 상태](B5_COUNT_ACCOUNTING.md). 아래는 B5-B3b3 당시 기록이다.

## 이번에 완료한 범위

실제 생성 요청을 보내는 내부 dispatcher에 **동일 입력의 최신 실측 결과를 요구하는 검사**를 추가했다. 앞선 합성 6장 실측 7,199토큰을 고정값으로 쓰거나, 과거 검사 파일을 운영 승인으로 가져오지 않는다. 기존 전송 동의·입력 상한·프로젝트 한도 검사도 그대로 필요하다.

- 실측 결과가 없거나 만료·철회됐으면 전송하지 않는다. 검증기 자체가 없으면 worker는 `disabled`다.
- 프로젝트, 모델, 지침 버전, 승인 ID, 승인 manifest 및 전체 생성 요청 fingerprint가 모두 같아야 한다. 전체 요청에는 대상/문맥 이미지, 시스템 지침, 응답 schema와 메타데이터가 포함된다.
- 실측량은 정책·준비 보고서·검토된 입력 상한 중 가장 작은 값 이하여야 한다. **실측 결과는 입력 상한 증명을 대체하지 않는다.**
- 입력 검사 뒤 이미지나 메타데이터가 바뀌면 차단한다. 전송 기록 전, 공급자 한도 차감 전, 저장소의 최종 잠금 안, 실제 전송 시작 콜백에서 다시 확인한다.
- 한도 차감 뒤 취소·만료돼 전송하지 못한 경우에도 이미 확정한 공급자 차감은 보존한다. 불확실한 요청 슬롯을 임의로 돌려주지 않는다.

## 실측 결과 보관과 신뢰 경계

`GeminiInputMeasurements`는 짧게 유효한 실측 결과를 보관하는 구체 클래스다. HTTP/환경변수/사용자 입력 숫자/과거 JSON을 등록하는 공개 기능은 없다. 현재 프로세스에서 명시적 `measure()`가 성공한 결과만 보관하며 `inspect()`는 **외부 전송 없는 조회**다.

- 최대 64개, 이미지 원문 없이 식별자·해시·토큰 수·시각만 보관한다. 프로세스 재시작 시 비워지는 임시 근거이며 사용량 원장이 아니다.
- 유효기간은 측정 시작부터 최대 30초다. UTC 일일 예산 또는 태평양 공급자 날짜를 넘으면 무효다. 시계가 뒤로 가면 근거를 폐기한다.
- 취소/철회/시간 초과 후 도착한 성공 응답은 등록하지 않는다. 측정의 기본 제한은 20초이며 재시도하지 않는다.
- 같은 인스턴스의 동시 측정을 막는다. 취소를 무시하는 실행기가 남아 있으면 그것이 실제 종료할 때까지 다음 측정도 막는다. 이는 여러 프로세스의 공유 사용량 제한을 대신하지 않는다.
- 결과 복사본의 숫자·승인·유효기간을 바꾸거나 유효 ID만 빌려도 통과하지 않는다. 최종 검사에서는 보관된 전체 레코드와 비교한다.

### 아직 구현하지 않은 부분

`MeteredGeminiInputCounter`는 **별도 사용량 기록을 보장해야 하는 신뢰 의존성의 계약일 뿐, 실제 Google 호출 구현이 아니다.** 이번 시험에서는 가상 실행기를 주입했다. 서버 시작·HTTP·사용자 화면에 실제 실행기를 연결하지 않았고, 위 클래스도 기본은 측정 불가다.

`countTokens`는 입력을 Google에 보내는 별도 요청이다. 현재 개별 요청 원장/예산/전송 허가는 `generateContent` 한 번을 기준으로 하므로, 그 허가 안에 토큰 계산까지 숨기면 안 된다. 실제 실행기는 계산 요청 자체의 동의·현재 소유권·검토된 입력 상한·프로젝트 한도를 확인하고 **독립적인 내구성 있는 전송 기록과 한도 차감**을 확보해야 한다. [Google 토큰 계산 요청 계약](https://ai.google.dev/api/tokens)

## 검증 결과

- 신규 19개: 실측 모듈 12개 + dispatcher 경계 7개. 외부 API를 사용하지 않는 가상 실행기/로컬 저장소 시험이다.
- 기본 검사: **processor 442 + client 4 = 446개**, 실패/건너뜀 0. 타입 검사·processor 빌드·린트·Site 빌드 통과.
- 별도 실제 PostgreSQL 16.15: **23/23 재통과**, migration `0000–0008`, 다중 연결·차감·잠금·정산/롤백 회귀 확인. 기존 시험이며 새 자동 토큰 계산 흐름을 실제 DB/Google까지 연결한 증거는 아니다.
- 합계 **469개**. 반복 실행한 개별 시험은 중복 합산하지 않았다.
- 격리 DB의 시험 컨테이너/tmpfs 자료는 정리했다. 기존 DB/사용자 자료는 변경하지 않았다.
- 이번 단계의 Google 요청 **0회**. 운영 DB/Storage, 키·과금 설정, UI, 푸시·배포는 변경하지 않았다. 앞선 실제 호출 결과는 [합성 실측·생성 기록](B5_QUOTA_INPUT_VERIFICATION.md)에 별도로 보존한다.

## 다음 단계 — B5-B3b4

1. `countTokens`와 `generateContent`를 구분하는 요청 원장·예약·정산 계약을 설계한다. 생성 재시도 차수를 계산 요청용으로 재사용하지 않는다.
2. 계산 요청도 중복/응답 유실/취소/재시작 때 한 번만 차감하고, 전송 여부가 불확실하면 사용량을 보존하도록 구현·검증한다.
3. 그 뒤에만 실제 계수 실행기와 실측 결과 보관을 작업 흐름에 연결한다. 모델별 전체 입력 상한, 무료 프로젝트/모든 호출자의 공유 한도 근거, 실제 준비 검증기·운영 DB/저장소 조건은 별도로 충족해야 한다.

실제 추가 전송과 배포는 해당 단계에서 범위·무료 조건·승인을 확인한 뒤 진행한다. 이번 로컬 완료를 사용자 영상 자동 분석 또는 공개 서비스 완료로 해석하지 않는다.
