# 개인정보 직접 확인 저장 — 2026-09-20

원래 개발 계획의 E1을 구현한 로컬 체크포인트다. 기존 계획의 목표·완료 조건을 바꾸지 않았다. **로컬 코드/UI와 실제 PostgreSQL 검증까지 통과했으며, Replit 실환경 완료나 게시 기능 완료로 표시하지 않는다.** 공개 공유, 개인 영상 AI 전송, Replit/Google 설정은 바꾸지 않았다.

## 저장 계약

- 문서 v1을 계속 읽되 모든 확인은 미확인으로 해석한다. 읽기만으로 DB를 수정하지 않는다. 저장된 초안에서 작성자가 처음 확인 동작을 하면 v2의 `privacy` 기록을 같은 초안 JSONB에 저장한다. DB 테이블/DDL 변경은 없다.
- 기존 단계의 `privacyReview: pending`은 호환용 표식이다. 실제 확인 여부는 서버가 v2 기록과 현재 입력을 대조한 결과만 사용한다. 구버전 서버는 v2를 읽지 못하므로 v2 저장 후 구버전으로 무작정 되돌리지 않는다.
- 제목, 단계 문구, 단계 화면을 각각 확인한다. 제목/문구 수정은 해당 텍스트 확인만 취소한다. 가림 수정은 해당 화면 확인과 masked 결정을 취소한다. 프레임 교체/병합은 이전 프레임의 확인을 가져오지 않는다. 편집 후 되돌려도 취소된 확인은 자동 부활하지 않는다. 포인터 이동은 개인정보 확인을 취소하지 않는다.
- 확인 지문은 서버에서 guide·미디어 입력 지문·프레임 소속·문구·가림·처리 방식 버전에 묶는다. 최신 성공 AI 결과의 후보는 서버 기록에서 읽는다. 새 결과가 생기면 동일 후보여도 예전 결정/단계 확인을 재사용하지 않는다. AI 결과 조회와 확인 저장은 새 AI 실행을 하지 않는다.
- 각 후보는 pending/masked/dismissed다. masked는 해당 프레임의 켜진 가림 영역 하나가 후보 전체를 덮을 때만 허용한다. 화면상 visible=false여도 enabled=true면 실제 가림으로 취급한다. 삭제/비활성화/이동된 가림으로 확인을 유지하지 않는다. 후보 값/OCR 원문을 새로 저장하지 않는다.
- 모든 후보를 결정해야 화면 확인을 저장할 수 있다. 후보 0건도 화면·문구 직접 확인을 생략하지 않는다. 모든 확인이 저장돼도 `publicationEnabled: false`이고 공개 경로/자산을 만들지 않는다. 이는 작성자의 판단 기록이며 사람의 실제 시선이나 개인정보 안전을 증명하는 장치가 아니다.

## API와 경합

- 소유자 Bearer 인증 아래 `GET /api/guides/:guideId/draft/privacy`로 현재 저장본과 유효 확인 상태를 읽는다. 읽기는 no-store이고 저장소 이미지·AI를 호출하지 않는다.
- 같은 주소의 POST는 `review-privacy` 명령 하나만 받는다. expectedRevision, expectedInputFingerprint, expectedReviewFingerprint, mutationId와 제목/문구/화면/후보의 명시적 동작이 필요하다. 쿼리 인증, 추가 필드, 임의 프레임·후보·가림 참조를 거절한다.
- JSON·PostgreSQL 공통 전이를 기존 부모 가이드 잠금 아래 실행한다. 삭제·미디어 교체·다른 창 수정·새 AI 후보가 먼저 반영되면 오래된 요청은 거절한다. 바로 직전 동일 요청의 응답 유실 재전송만 같은 결과를 반환하며 다른 요청 내용은 덮어쓰지 않는다.
- 일반 초안 PUT이나 내부 save-draft는 확인 기록을 임의 생성/승인할 수 없다. 기존 서버 기록을 그대로 유지하거나 편집 규칙에 따라 취소한 기록만 받는다. v2→v1 다운그레이드로 확인 계약을 우회할 수 없다.
- 확인 저장과 비공개 초안 보존 시각 갱신은 한 트랜잭션이다. 읽기/충돌/재전송은 보존 시각을 연장하지 않는다. 저장 실패는 확인 완료로 응답하지 않는다.
- 확인 명령은 8 KiB, 일반 초안은 1 MiB의 JSON 상한을 적용한다. v2의 후보 기록이 추가된 24단계·프레임당 최대 20개 가림 문서도 다시 편집할 수 있도록 종전 64 KiB 초안 상한을 확장했다. 압축 본문은 계속 금지하고 인증·분당 60회·문자/개수/좌표 검사는 유지한다.

## 편집기 연결

가림 영역 편집 안에서 후보 결정과 화면·문구·제목 확인을 수행한다. 화면 확인 버튼은 현재 저장 revision의 실제 처리본 미리보기를 연 뒤 사용할 수 있다. 저장 중/실패/충돌/미전송 변경이 있으면 확인을 막는다. 확인 저장 응답은 기존 편집 내용이 그대로일 때만 자동 저장 기준 revision에 반영한다. 입력이 바뀌었으면 이를 덮지 않고 최신 저장본 확인을 요청한다.

브라우저의 기존 가림 객체와 서버의 정규화된 객체는 속성 순서가 다를 수 있었다. UI 시험에서 이 차이를 내용 변경으로 오인해 후보 확인 뒤 불필요한 저장이 실패하는 문제를 발견했다. 순서가 고정된 값 비교로 수정하고 재현 검사를 추가했으며 동일 UI 흐름을 재검증했다. 후속 리뷰에서 공백 정규화도 확인 취소 전에 수행하도록 보완하고 회귀 검사를 추가했다. 가림 추가·수정·삭제나 순서 변경 등 실제 값의 변경 검사는 유지한다.

## 검증 및 한계

- 새 일반 검사: 서버 17개(전이 12 / HTTP 5), 클라이언트 8개. legacy/v2, 위조·다운그레이드, 후보/활성 영역 연결, 변경·되돌리기·새 AI 결과, 재전송·충돌·삭제·실패 롤백, 큰 초안, 클라이언트 응답 검증과 자동 저장 결합을 검사한다.
- 최종 전체 **897개 통과**(이관 99 / 서버 699 / 클라이언트 99), 실패·취소·생략 0, 종료 코드 0. 큰 문서 및 공백 정규화 회귀 검사까지 포함한다.
- 서버/화면 제품·테스트 타입 검사와 양쪽 빌드 통과. 기존 화면 소스맵 경고와 578.53 kB 번들 경고는 남는다. 의존성을 설치/교체하거나 lockfile을 바꾸지 않았다.
- 컴퓨터 사용 스킬로 개인 자료 없는 로컬 합성 가이드에서 제목·문구·화면 확인 저장, 수정 후 해당 확인만 취소, 새 가림 추가 뒤 후보 masked 저장, 실제 PNG 확인 뒤 화면 확인, 새 탭/새로고침 복원을 확인했다. 첫 단계의 흐름을 검증했으며 모든 단계 확인 완료까지 수동 통과했다고 주장하지 않는다.
- 후보는 시험 서버가 저장소에 가상 결과를 넣어 재현했고 외부 AI는 호출하지 않았다. 개인 영상/계정/키나 Replit DB/Storage에는 접근하지 않았다.
- 320px에서 긴 버튼이 가로로 넘치는 문제를 수정하고 최종 화면에서 줄바꿈을 확인했다. 수정 전 DOM 폭은 303/330이었으나 수정 후 DOM 수치 조회는 도구 타임아웃이어서 수치 측정 통과로 세지 않고 스크린샷 확인만 기록한다. 임시 viewport를 복원하고 시험 탭을 닫았다.
- 임시 서버와 해당 합성 저장 폴더는 종료/정리 완료, 원래 합성 MP4는 보존했다. 마지막 status와 quit을 동시에 보낸 보조 도구의 상태 조회는 정리와 경합해 오류였지만 종료 로그 `PRIVACY_UI_CLEANED`와 종료 코드 0을 확인했다. 이후 보조 도구 명령을 직렬화했다. 마지막 요청 카운터가 확보됐다고 표시하지 않는다.
- 실제 PostgreSQL 통합 검사 2개를 추가했다. 최초에는 Docker 경로 미지정과 엔진 파이프 부재로 실행 전 중단됐으나, 사용자의 Docker 실행 확인 후 코드 `a0f4e01`에서 재개했다. PostgreSQL 16.15의 전체 통합 검사 **103개 통과**, 실패·취소·생략 0, 종료 코드 0이다. 새 검사에서 v2 확인의 재접속 복원·revision 충돌·편집 무효화·삭제 후 오래된 요청 거절과, 실제 트리거 실패 시 JSONB/보존 시각의 원자적 롤백을 확인했다.
- 기존 로컬 이미지로 생성한 loopback 전용 일회용 컨테이너 `showme-b5-5550f9c7fe884f7f855e2a155ab0b32e`와 임시 데이터는 검사 후 제거 로그를 확인했다. 호스트 영구 마운트, 앱 .env, 운영 DB, 개인 영상은 사용하지 않았다. 외부 AI/Storage는 모의 응답이며 실제 외부 요청 검증이 아니다. 일반 897개는 직전 실행 결과이고 이번 후속에서는 DB 통합 검사만 실행했다.
