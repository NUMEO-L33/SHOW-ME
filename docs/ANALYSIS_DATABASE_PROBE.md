# B5 DB 실행 조건 읽기 전용 검사

2026-09-18. `PostgresAnalysisDatabaseProbe`는 저장소 객체가 사용하는 `repository.database`를 받아 DB 조건을 조회하는 내부 검사다. **운영 환경의 준비 완료 근거 발급기는 아니며 결과는 항상 `authorizesAnalysis: false`다.** 서버 시작/HTTP에는 연결하지 않았다. 후속으로 명시적으로 실행하는 별도 DB 점검 명령만 추가했다.

## 확인하는 범위

- `repeatable read`, `read only` 트랜잭션을 사용하고 실제 읽기 전용 설정도 확인한다. 복제 대기 서버와 기본 읽기 전용 연결은 거절한다.
- Drizzle이 사용하는 방식으로 로컬 migration SQL의 해시/시각을 읽어 DB의 전체 migration 이력과 비교한다. 마지막 버전 숫자만으로 통과시키지 않는다. SQL을 적용하거나 이력을 수정하지 않는다.
- 앱이 쓰는 public의 11개 테이블이 영속 일반 테이블이며, 현재 search path도 같은 테이블을 가리키는지 확인한다. RLS가 켜진 경우 보류한다.
- 현재 역할의 schema USAGE 및 각 테이블 SELECT/INSERT/UPDATE/DELETE 권한을 확인한다. 권한 확인을 위해 데이터를 쓰지는 않는다.
- 코드의 컬럼 이름·타입·필수 여부 및 즉시 유효한 고유 키와 실제 catalog를 비교한다.
- CHECK 제약 이름과 검증 상태를 비교하고, 계수 원장의 status 제약은 `launch_claimed`를 포함한 정확한 허용 집합인지 별도로 확인한다.
- 전역 회계 중단 행은 정확히 하나이고 `{halted:false}`여야 한다. 중단/누락/손상 상태를 자동으로 복구하거나 초기화하지 않는다.

원본 영상·화면·초안·편집 키를 조회하지 않는다. 데이터 행 조회는 전역 중단 행 한 개와 migration 이력으로 한정한다. 출력에는 연결 문자열, DB/계정 이름, migration 내용, 원문 DB 오류를 넣지 않는다.

## 시간 제한과 취소

호출자 대기는 기본 최대 4초, DB statement는 2초, lock 대기는 1초다. 같은 검사 객체에서 중첩 실행하지 않는다. 취소/시간 초과 뒤 늦게 연결되거나 응답한 작업은 다음 조회를 시작하거나 관측값을 반환하지 못한다. 실제 transaction이 끝날 때까지 사용 중 상태를 유지한다. 공유 pool 또는 다른 작업의 연결/잠금을 강제 종료하지 않는다.

## 이 결과가 증명하지 않는 것

이는 조회 시점의 **DB 한 부분 관측값**이며 잠금 하의 최종 예산/동의/소유권 검사를 대체하지 않는다. 모든 CHECK 식의 의미, FK·trigger·함수 전체, 모든 행의 무결성, TLS/네트워크 ACL, 서버 운영 권한, 저장소 IAM/백업, 외부 프로젝트 사용량, 무료 등급, 호스팅 지출, 입력 승인/토큰 상한은 검증 범위 밖이다. CHECK 이름과 검증 상태 일치만으로 전체 스키마가 변조 불가능하다고 주장하지 않는다.

실행 환경 근거를 발급하려면 저장소·실행기·프로젝트/키·한도·호스팅 근거와 연결하고 변경 시 철회하는 과정이 여전히 필요하다. 이 관측 결과를 HTTP/env JSON으로 복사해 이전 readiness 연결부에 넣거나 `isCurrent:()=>true`로 감싸지 않는다.

## 명시적 실행 명령 — 운영 환경에서는 아직 실행하지 않음

`analysis-database-check.ts`는 현재 프로세스의 `DATABASE_URL`로 별도 연결 하나를 만들고 위 검사를 호출한다. **실행 중인 API 서버의 pool을 검사하는 것이 아니므로, 같은 설정·배포를 쓰는지 별도로 확인해야 한다.** 로컬 셸의 성공을 Replit 결과로 옮겨 적지 않는다.

아래는 코드가 반영된 환경에서 대상 프로젝트와 개발/운영 구분을 확인한 뒤 별도 승인을 받아 실행할 명령이다. 현재 Replit에는 새 명령을 반영하지 않았다.

```sh
pnpm --filter @workspace/api-server check:analysis-db --help
pnpm --filter @workspace/api-server check:analysis-db --configured-database --read-only
```

- 두 실행 인수가 모두 있어야 접속한다. 인수 없음·오타·중복·추가 URL/쓰기/AI 옵션은 종료 코드 2로 거절한다. `--help`는 접속하지 않는다.
- `.env`를 읽거나 설정을 바꾸지 않으며, URL·암호를 명령 인수로 받지 않는다. 연결 대상은 기존 `DATABASE_URL` 하나다. DB 이름·주소·계정·연결 문자열·원문 오류는 출력하지 않는다.
- 대상 URL의 프로토콜·호스트·포트·계정·암호·DB 이름을 확인한다. PG 환경변수가 대상·역할·options를 바꾸지 않도록 연결 필드를 명시한다. URL의 host/options 재지정, 사용자 인증서 파일 경로, 추가/중복 옵션은 거절한다.
- 원격 대상은 `sslmode=require` 또는 `verify-full`만 허용하고 인증서 검증을 명시적으로 유지한다. 비암호화는 정확한 loopback 주소만 허용한다. 사용자 인증서·고급 연결 설정·`channel_binding` 등은 자동으로 무시하거나 완화하지 않고 거절한다. 지원하지 않는 설정을 통과시키려고 기존 Secrets를 임의로 변경하지 않는다. 원격 TLS 접속 자체는 이번에 시험하지 않았다.
- 연결 3초, statement 2초, lock 1초, 검사 4초 제한을 두고 명령 자체는 10초 최종 제한을 둔다. 공유 서버가 아닌 이 명령의 연결만 닫는다. DB schema/행을 쓰거나 migration/중단 해제/복구/Storage/AI/서버 시작을 실행하지 않는다. 연결 세션 설정과 통계는 생길 수 있다.
- 종료 코드 0은 **DB 부분 점검 통과**다. 출력의 `ready:false`, `authorizesAnalysis:false`는 의도된 결과다. 종료 코드 1은 대상 설정 또는 점검 실패이며, 거절 원문을 공개하거나 자동 복구하지 않는다.
- 정상/미적용 스키마/중단 상태/잘못된 암호의 실제 CLI 자식 프로세스 4개를 포함해 PostgreSQL **70개 모두 통과, 실패·생략 0, 종료 코드 0(33.11초)**. 환경 변수로 다른 PG 대상/options를 주어도 기존 URL 대상만 검사했고, 가이드·초안·중단 행 불변, 미적용 schema의 미생성, 연결 종료, 민감값 비출력과 AI 비활성 결과를 확인했다. 일회용 컨테이너 정리도 확인했다.
- 새 단위 검사 9개는 실행 동의 인수, 설정 검증, 취소, 안전한 오류, 기본 CLI의 비접속, 응답 없는 loopback 연결의 시간 제한/종료, startup 미연결을 다룬다. 최초 테스트 작성의 괄호 누락과 드라이버 `replication` 옵션 타입 선언을 바로잡았다. 운영 동작의 실패나 DB 변경은 아니었다.
- 최종 일반 회귀 **719개(이관 91 + 서버 571 + 클라이언트 57), 실패·생략 0, 종료 코드 0**, API 제품/테스트 타입 검사 및 API 빌드 통과. 의존성·스키마·기존 서버 시작 코드는 바꾸지 않았다. CLI는 소스/tsx로 실행하는 별도 도구이며 배포 번들의 자동 실행 경로가 아니다.

실환경 근거 발급/갱신/철회, 저장소·키/프로젝트·무료 조건·호스팅·정확한 입력 상한 검증은 여전히 미구현/미연결이다. 이번 명령 추가로 이 조건들이 충족됐다고 간주하지 않는다.

## 이전 로컬 검증 상태 — DB 검사 본체

- `tests/analysis-database-probe.test.ts`: 모의 catalog의 정상/실패, 전체 migration 비교, 읽기 전용 transaction, 사전/지연 취소, 시간 초과/진행 슬롯, 안전한 오류, startup 미연결과 SQL/시각 회귀 등 **18개 통과**.
- 최종 일반 회귀 **710개(이관 91 + 서버 562 + 클라이언트 57), 실패·생략 0, 종료 코드 0**. API 제품/검사 타입 검사와 API 빌드도 재통과했다. 앞선 일반 708개에 아래 재발 방지 2개가 추가됐다.
- `integration/postgres.test.ts`: 신규 19개를 포함한 **실제 PostgreSQL 16.15 검사 66개 모두 통과, 실패·생략 0, 종료 코드 0(22.63초)**. 정상 조회의 데이터 불변, migration/컬럼/키/제약 누락, 구형/약화된 계수 상태 제약, RLS, 중단 행, 실제 잠금 경합, 읽기 전용 역할, search path 가림과 연결 설정을 검사했다. 변경 가능한 음성 검사는 손상시키기 전 정상 통과를 먼저 확인하며, 잠금 검사는 실제 DB 잠금 대기 상태도 확인한다. 기존 47개 결과를 재사용한 것이 아니라 전체를 재실행했다.
- 재부팅 후 첫 실제 실행은 64개 통과·2개 실패였다. Drizzle raw timestamp가 Date가 아닌 문자열인데 Date를 요구한 문제와, 테이블 이름 배열이 SQL 행 매개변수로 펼쳐진 문제를 확인했다. 시각은 안전한 정수 epoch 밀리초로 조회하고 배열은 `sql.param` 하나로 바인딩하도록 수정했다. 수정 전 재발 방지 검사 2개의 실패를 확인했고 수정 후 단독 18개·실제 66개·일반 710개를 통과했다. 거절 조건·잠금 시간 제한을 완화하거나 원문 DB 오류를 노출하지 않았다.
- 기존 설치/이미지를 쓰는 격리 실행기를 사용했으며 운영 환경값은 제외했다. 두 실행 모두 `postgres_fixture_removed`로 해당 임시 DB/컨테이너 정리를 확인했다. 시험 자료는 tmpfs의 일회용 데이터이며 보관하지 않는다. 새 설치/이미지 다운로드, Replit DB·Storage, 외부 AI, 사용자 영상 또는 CDP에 접근하지 않았다.
- 이전 Docker 시작/종료 및 named pipe 오류는 **사용자 재부팅·Docker 실행 후 해소**됐다. Docker 29.7.2 응답을 확인한 뒤 검사했다. 이번에는 Docker 앱을 재시작하거나 강제 종료·재설정하지 않았으며 사용자가 켜 둔 상태를 유지했다.
- 변경은 로컬이며 커밋·푸시·Replit 반영 전이다. DB 부분 조회 검증은 완료했으나, 실제 근거 발급/갱신/철회와 운영 대상 연결 검증은 여전히 남아 있다. 외부 AI와 서버 시작 연결은 계속 꺼져 있다.
