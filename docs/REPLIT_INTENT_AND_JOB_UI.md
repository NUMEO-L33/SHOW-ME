# 제작 의도 입력과 작업 상태 표시 — 2026-09-17

대상: `codex/replit-migration-hardening`. `39656c8` 이후의 프런트엔드 보완이다.

## 바뀐 흐름

1. 파일 선택 또는 녹화 완료 후 목적(필수), 대상(선택), 추가 요청(선택)을 입력한다. 선택만으로 업로드하지 않는다.
2. **장면 추출 시작**을 누르면 제작 의도를 해당 작업의 복구 키와 함께 브라우저에 저장하고, 저장값 재확인이 성공해야 영상 업로드를 시작한다.
3. 실제 서버에서 추출 완료 응답을 받은 뒤 검토 화면을 연다. 제목에는 입력 목적을 사용하며, 기존 작업은 서버 제목이나 중립적인 기본 제목을 사용한다. 은행 예시 제목은 사용자가 예시를 선택할 때만 사용한다.
4. 검토 화면의 **제작 의도 수정**으로 내용을 변경할 수 있다. 저장 실패는 성공으로 표시하지 않으며, 기존 복구 키와 기록을 유지한다.
5. 삭제 중에는 삭제 전용 화면을 표시한다. 추출 단계나 12%를 표시하지 않는다. 서버의 204 완료 응답 후에만 복구 기록을 지우고 첫 화면으로 돌아간다.

제작 의도는 **이 브라우저의 해당 사이트 저장소에만 저장**한다. 입력 중인 값은 시작 버튼을 누르기 전까지 메모리에만 있다. 새로 고침 복구는 작업 시작 후 저장된 기록에 한정한다. 다른 브라우저·다른 도메인으로 동기화되지 않으며 사이트 데이터를 지우면 사라진다. 민감한 정보는 입력하지 않도록 안내한다.

**AI에 제작 의도를 전송하거나 설명 생성에 적용한 것은 아니다.** 편집한 설명·제목·누를 위치의 서버 저장, 개인정보 가림, 공개 공유도 아직 연결 전이다. 제작 의도 변경으로 기존 편집 내용을 덮거나 자동 재분석하지 않는다. 홈·추출·검토 화면에 이 제한을 명시한다.

## 오류와 삭제 확인

- 서버가 보고하지 않은 진행률을 임의로 표시하지 않는다. 파일 전송률과 서버 처리 진행률을 구분하고, 전송 100%가 접수 완료는 아님을 안내한다.
- 연결 실패·인증 실패·작업 조회 404·잘못된 응답에서는 진행 막대를 숨기고 복구 정보를 유지한다. 새 업로드는 자동으로 만들지 않는다.
- 조회 404는 기존 업로드 확인 유예 시간 안에서만 자동 조회하며 이후 수동 확인으로 전환한다. 401/403과 잘못된 응답은 수동 확인으로 전환한다.
- 삭제 404는 미존재와 권한 불일치를 구분할 수 없어 삭제 성공으로 처리하지 않는다. 기록을 유지하고 **삭제 다시 확인**을 제공한다. 202는 삭제 대기, 204만 완료다.
- 조회·삭제 요청은 응답 본문 읽기까지 15초 제한을 두며 자동 리디렉션을 따르지 않는다. 실패 시 키·내부 URL·원시 네트워크 오류를 화면에 표시하지 않는다.

## Replit 반영 후 확인

[안전 반영 순서](REPLIT_UPDATE.md)에 따라 변경 없는 상태를 확인하고 같은 브랜치를 fast-forward로 갱신한다. 검사·빌드 성공 뒤 기존 Workflows만 재시작한다. Shell에서 같은 포트의 서버를 중복 실행하지 않는다.

1. 처음에는 파일 없이 홈의 중립적인 제목을 확인한다.
2. 개인정보 없는 합성 영상을 선택하면 제작 의도 입력란이 나타나는지 확인한다. 목적을 비워 두면 업로드가 시작되지 않아야 한다.
3. 목적을 입력해 한 번 시작하고, 실제 추출 결과와 입력 목적을 확인한다. 새로 고침 뒤 목적/추가 요청이 복구되는지 확인한다.
4. 전체 삭제를 누르면 삭제 전용 화면이 보이고 완료 응답 뒤 홈으로 돌아가는지 확인한다. 오류가 나면 성공으로 간주하지 말고 화면과 상태를 확인한다.

`main` 병합·Publish·자동 AI 활성화·실제 Gemini 전송은 이 반영 절차에 포함되지 않는다.
