# 비공개 자료 7일 / 게시본 15일 보존 분리

2026-09-21 로컬 구현. 원래 개발 MD의 목표·완료 조건은 변경하지 않는다. 게시 기능의 인증 API·공개 응답·화면·자동 게시 실행은 아직 연결하지 않았다.

## 기준과 상태

- 비공개 자료는 기존 정책을 유지한다. 마지막 정상 편집/개인정보 확인 저장 후 7일이 지나면 기존 정리 루프가 만료를 확정한다. 읽기·저장 재전송·게시·정리 재시도는 이 시각을 늘리지 않는다. 구버전 데이터는 guide와 draft 시각을 모두 확인한다.
- 게시본은 첫 게시 후 15일 고정이다. 재게시로 연장하지 않는다. 첫 게시가 편집보다 늦으면 두 만료일도 다르다.
- 게시 이력이 없는 초안은 기존 전체 삭제 경로를 유지한다.
- 게시 이력이 있는 ready 가이드는 `failed / PRIVATE_MEDIA_EXPIRED`로 비공개 만료를 표시한다. 단계·편집 초안·AI 실행/결과를 지우고, 파일명·원본 메타데이터를 만료 안내로 대체한다. 과금 예약의 상세 내용은 제거하되 숫자·미확정 사용량 정산 근거는 유지한다.
- 진행 중 게시를 취소하고 게시되지 않은 작업의 설명 내용을 지운다. 늦은 저장을 추적할 소유권/버전/자산 기록은 보존한다. 활성 게시본과 게시된 불변 이력은 유지한다.
- 새 편집·분석·미디어 재처리·게시 준비는 차단한다. 기존 이미지 티켓도 원본 접근 권한을 유지하지 못한다. 공유 철회·전체 삭제는 계속 가능하다.
- 활성 게시가 없거나 첫 게시+15일이 되면 비공개 만료 가이드를 전체 삭제 대상으로 전환한다. 게시 접근은 정리 전이라도 정확한 15일 경계부터 거부한다.

## 실패와 경합

`expirePrivateDraft`는 최신 guide/draft/게시/자산 상태와 관측한 `updatedAt`을 부모 가이드 잠금 아래 확인한다. 원본 정리 목록 저장, 개인정보 제거, 작업 취소, 자산 상태 변경을 한 번에 확정한다. PostgreSQL은 각 INSERT/UPDATE/DELETE의 실제 반영 건수를 확인한다. 예외나 조용히 무시된 쓰기는 전부 롤백한다. 동시에 들어온 정상 편집이 먼저 저장되면 오래된 만료 요청은 실패한다. 만료가 먼저면 뒤늦은 편집을 거부한다.

`private_media_cleanup`에는 해당 가이드의 원본/프레임 키만 기록한다. 다른 가이드, 경로 역참조, 게시 처리본 키는 받지 않는다. 정리 목록이 남아 있으면 부모 행을 지울 수 없다. 삭제 실패·재시작 뒤에도 같은 목록으로 재시도한다. 원본과 함께 비활성 처리본도 정리하되 활성 게시 자산은 저장소 계층에서 다시 보호한다.

원격 쓰기의 실제 종료를 확인하지 못하면 삭제 완료로 처리하지 않는다. 만료/취소 상태로 쓰기를 차단하고 원장과 삭제 대기를 유지한다. 새 정리 작업은 최대 20행 keyset 순환과 기존 저장소 제한시간/늦은 삭제 추적으로 제한한다. 한 행의 실패로 계속 같은 첫 행만 선택하지 않는다.

## 저장 형식과 적용 범위

- 새 migration `0017_private_media_cleanup.sql`: 정리 목록과 부모 삭제 제한 FK. 기존 SQL 파일은 변경하지 않는다.
- JSON v9: `privateCleanup` 추가. v1–v8은 읽을 때 기존 내용을 바꾸지 않고 다음 저장에서 변환한다. 정리 목록의 중복/소유권 손상은 거부한다.
- 새 런타임 역할 생성 코드에 해당 테이블 권한을 포함한다. 기존 Replit 역할·DB에는 적용하지 않았다. 배포 시 0014–0017 및 역할 권한을 별도 확인해야 한다.
- 기존 비공개 정리 루프와 전체 삭제 HTTP에 연결했다. 공개 HTTP/게시 worker는 여전히 미등록이다. 만료 화면은 현재 오류 안내를 사용하며 전용 게시 관리 UI는 다음 단계다.

## 검증과 한계

합성 입력과 로컬 일회용 DB만 사용했다. JSON/HTTP에서는 7일 직전·경계, 15일 경계, 늦은 첫 게시, 최근 편집, 재연결, 삭제 실패, 미확정 writer, 과거 이미지 티켓, 전체 삭제를 검사한다. 실제 PostgreSQL에서는 모든 만료 쓰기 경계의 실패/무시 롤백, 실제 부모 잠금 순서, 개인정보 정리와 정산 숫자 보존, 재연결·철회·삭제를 검사한다. 최종 실행 결과는 `SESSION_CHECKPOINT.md`에 기록한다.

7일은 기존 주기적 정리 정책이며 모든 요청에서 정확히 7일째 즉시 물리 삭제를 보장하는 구조는 아니다. 서버 중지·저장소 장애·미확정 쓰기에서는 정리가 늦어질 수 있다. 이미 내려받은 화면은 회수할 수 없다. 게시 이력이 있는데 미디어 상태가 비정상 failed로 바뀐 경우는 원본 쓰기 종료를 추정하지 않고 자동 분리 만료를 보류한다. 정상 제품 흐름에서 ready 게시 가이드의 미디어를 재처리하는 경로는 열지 않는다.

Replit 저장소에서의 불확실 쓰기 해소·실환경 보존/삭제 검증, 인증 API·공개 이미지 스트리밍 권한/no-store, 자동 게시 실행 및 UI 연결은 남아 있다. 이 문서는 E3 전체 완료나 운영 배포 완료를 의미하지 않는다.
