# 비공개 편집 자동 저장 — 2026-09-17

대상: `codex/replit-migration-hardening`, `5ba696d` 이후 프런트엔드 보완.
이 문서는 [수동 서버 저장 단계](REPLIT_SERVER_DRAFT.md)의 저장 UX를 대체한다.

**2026-09-18 후속 변경:** 승인된 보관 정책은 마지막 성공한 편집 저장부터 7일이다. 초안과 원본 보관을 함께 연장하며 조회·실패·충돌·동일 요청 재전송은 연장하지 않는다. 기존 초안의 최근 저장 시각도 만료 판단에 반영한다. 저장/삭제 경합 및 롤백 검사와 전체 회귀 664개가 통과했고 이후 커밋·푸시 승인을 받았다. Replit 실행 반영은 별도다. 상세 범위와 한계는 [녹화·비공개 전송 검증](REPLIT_RECORDING_PRIVACY.md)의 최신 변경을 따른다. 아래는 최초 자동 저장 도입 이력이다.

## 변경 범위

- 이미 추출한 실제 가이드의 제목·설명·직접 지정한 누를 위치·단계 합치기/제거를 수정하면, 마지막 변경에서 약 1초 뒤 비공개 서버 초안에 자동 저장한다.
- 일반 저장 버튼은 없애고 `자동 저장 대기 → 자동 저장 중 → 자동 저장됨`을 표시한다. 오류 때만 **다시 저장**을 제공한다. 모바일에서도 본문 저장 상태를 확인할 수 있다.
- 저장 중에도 계속 편집할 수 있다. 요청은 한 번에 하나만 보내고, 그 응답의 버전을 사용해 다음 편집을 저장한다. 응답으로 입력 필드·현재 단계·제작 의도를 덮어쓰지 않는다.
- 한글 등 IME 조합 중에는 새 저장을 시작하지 않는다. 조합 종료 후 다시 약 1초를 기다린다. 빈 제목/설명 등 유효하지 않은 중간 입력은 전송하지 않으며 고치면 자동 저장을 재개한다.
- **제작 의도 수정** 창의 입력은 **적용** 전에는 전송하지 않는다. 적용하면 기존 제목을 유지하고 현재 편집과 함께 자동 저장한다. 취소하면 모달의 변경은 버린다.
- 실패·충돌 뒤에는 새 입력을 보존하고 자동 전송을 멈춘다. 수정만으로 재시작하지 않는다. **다시 저장**은 응답을 받지 못한 정확한 직전 요청부터 재확인한 뒤 새 변경을 저장한다. 기존 버전 검증/충돌 거부를 우회하지 않는다.
- **최신 저장본 불러오기**는 미저장 입력을 버린다는 확인을 거친다. 읽기 실패 시 입력을 유지하며 자동 전송도 중단한다.
- 미저장 변경·진행 중 저장·미해결 오류가 있으면 페이지 이탈 경고를 요청한다. 브라우저가 경고 표시를 생략할 수 있으므로 **자동 저장됨** 확인 전에 탭을 닫지 않는다. 종료 시 저장 성공을 보장하거나 백그라운드 전송으로 가장하지 않는다.
- 전체 작업 삭제/페이지 해제 시 예약 저장을 취소하고 진행 중 요청을 중단한다. 이미 서버에 도착한 요청의 처리 여부는 기존 서버 버전·삭제 잠금 규칙을 따른다.

## 바꾸지 않은 경계

영상 선택/녹화만으로 업로드하지 않는다. **장면 추출 시작**을 누르는 기존 업로드 절차, 접근 키, 서버 저장 API, 서버 DB/Storage, FFmpeg/Nix, 의존성·잠금 파일을 변경하지 않았다. AI 실행·개인정보 영구 가림·공개 공유를 연결하지 않는다.

화면 녹화의 종료 안전성 보완은 별도 미완료 항목이다. 자동 저장 검증을 녹화 보안 검증이나 운영 환경 전체 보안 감사로 취급하지 않는다.

## 검증

- Windows / Node 24.15.0: 자동 저장 상태/타이밍 검사 12개를 포함한 클라이언트 43개 통과, 실패·생략 0. ShowMe 앱/테스트 타입 검사 통과.
- 전체 `node scripts/run-tests.mjs` 실행도 종료 코드 0: 서버 493개와 클라이언트 43개 통과, 실패·생략 0. 첫 실행은 이 clone의 npm FFmpeg 실행 파일이 없어 실패했다. 기존 로컬 FFmpeg 6.1.1 / FFprobe 4.0.2를 `SHOWME_TEST_FFMPEG_PATH` / `SHOWME_TEST_FFPROBE_PATH`로 명시한 뒤 전체를 다시 실행했다. 검사·제한 시간·운영 버전 검증을 바꾸거나 실패 검사를 생략하지 않았다. 이는 Windows fixture 검증이며 Replit의 pinned headless 8.1.2 실사용 검증을 대신하지 않는다.
- 기존 로컬 Windows 네이티브 의존성 보조 환경을 사용한 Vite 7.3.6 production 빌드 통과. 앱 환경변수와 `.env`를 제외했다. 기존 UI 소스맵 경고와 약 530 kB 번들 크기 경고는 유지했다. 잠금 파일이나 의존성 허용 규칙을 변경하지 않았다.
- 격리 headless Chrome + 실제 로컬 HTTP API + 실제 JSON 저장소 + 실제 FFmpeg로 합성 3장면 영상을 사용했다. 제목/설명/위치의 버튼 없는 저장·새로고침, 모달 적용 전 의도 미전송, 적용 후 저장, 저장 중 추가 입력과 순차 전송, 503 실패, 커밋 후 응답 유실/동일 요청 재시도, 두 탭 충돌/명시적 재읽기, 합치기/단계 제거/전체 삭제, 모바일 저장·복원을 확인했다. 페이지 오류 0, AI 호출 0. 320/390/640/768px 가로 넘침 검사 통과.
- 브라우저 검사는 실제 Replit DB가 아닌 격리 로컬 저장소를 사용했다. Replit에서 이 자동 저장 버전의 실사용 확인은 아직 별도다.

이전 `5ba696d` 수동 저장 버전에서는 사용자가 Replit의 제목·설명·제작 의도·표시 위치·합치기/단계 제거 및 새로고침 복원을 확인했다. 소스/빌드에 새 API가 있어도 구 서버 프로세스가 계속 떠 있으면 `/draft`가 `NOT_FOUND`를 반환할 수 있으며, 당시 API 서버 재시작으로 해소했다. 이번 변경은 서버 API를 새로 추가하지 않는다.

## Replit 반영 후 확인

원격 반영이 확인된 뒤, 기존 변경이 없는 올바른 브랜치에서만 `git pull --ff-only`로 받는다. 현재 미저장 입력은 먼저 저장한다. 프런트엔드 변경이므로 새 API 서버를 Shell에서 중복 실행할 필요는 없다.

1. `node scripts/run-tests.mjs client`와 `PORT=20116 BASE_PATH=/ pnpm --filter @workspace/showme run build`를 실행한다.
2. 기존 ShowMe 웹 Workflow를 갱신/재시작하고 미리보기를 새로고침한다. 기존 합성 가이드를 사용하며 개인 화면 녹화는 하지 않는다.
3. 설명 또는 제목을 바꾸고 버튼을 누르지 않은 채 **자동 저장됨**을 기다린다. 새로고침 후 값이 유지되는지 확인한다.
4. 실패/충돌 문구가 나오면 복구 키나 작업을 삭제하지 않고 해당 문구를 확인한다. 충돌을 자동 덮어쓰기로 해결하지 않는다.
