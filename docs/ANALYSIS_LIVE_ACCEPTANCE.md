# 고정 합성 AI 실환경 검사 — 2026-09-20

기존 개발 계획과 완료 조건은 변경하지 않았다. 개인 영상이 아닌 동결 합성 JPEG 두 장으로, Replit의 실제 제한 DB 계정·App Storage·Google API를 연결해 검사했다. 새 키 교체 및 이전 키 삭제는 사용자 완료 보고를 근거로 했으며 키 원문을 다시 열거나 출력하지 않았다. 키와 프로젝트의 바이트 단위 대조를 새로 수행했다는 뜻은 아니다.

## 완료한 경로

- 기존 SHOW-ME 개발환경의 API health 200, 새 셸의 키 존재/형식, runtime/operator 연결 파일 존재를 비밀값 없이 확인했다.
- 기존 `check-private-access.mjs --run-synthetic` 통과: 합성 영상 업로드, 소유자 가이드/초안, 서명 이미지, 키 없음/잘못된 키 거절, 시험 가이드 삭제.
- 고정 JPEG 두 장은 서버 내부 시험 코드가 별도 UUID의 시험 가이드/프레임으로 저장했다. 이 AI 검사 자체가 영상 추출부터의 UI 검사를 다시 수행한 것은 아니다.
- 별도 운영자 CLI가 승인 기록과 10분 한정 합성 활성화를 저장했다. 별도 자식 프로세스는 runtime DB 로그인만 사용하고, 실제 `configuredAnalysisFactory`와 `createAnalysisLifecycle`를 같은 repository/storage에 연결했다. 운영자 연결을 앱 자식 환경에 전달하지 않았다.
- 자식 프로세스의 제품 `createProcessorApp`을 임시 loopback 주소에서 실행했다. 소유자 없는 요청의 404와 전송 동의 없는 요청의 400을 확인한 뒤 정상 동의 요청을 보냈다. 공개 서버의 AI 설정은 변경/재시작하지 않았다.
- 실제 Google `countTokens` **1회 HTTP 200**, `generateContent` **1회 HTTP 200**. 재시도/유료 fallback/다른 모델 전송은 하지 않았다.
- 결과 두 단계가 실제 PostgreSQL에 저장됐고, 제품 API의 초안 `persisted:true`, revision 1 및 repository 재조회가 일치했다. 생성 응답 사용량은 입력 **2,771**, 출력 **314** 토큰이었다. 이는 계수 요청까지 합친 총 토큰 수가 아니다.
- 운영 기록을 철회한 뒤 capabilities가 false, 새 실행 접수가 503이 됐으며 추가 Google 요청은 없었다.

## 정리 실패와 복구를 구별한다

최초 실행은 AI/저장/철회까지 통과했으나 최종 삭제 확인에 실패하여 전체 `PASS`가 아닌 실패로 종료했다. 읽기 전용 확인에서 이 시험 가이드만 `failed / DELETION_PENDING`, 분석 결과는 `succeeded`, 공통 제어는 halted였다. 최초 실패의 정확한 예외 원인은 출력되지 않았으므로 시간 초과로 단정하지 않는다.

삭제 요청 대기 한도를 보완하고 `--cleanup-only`를 추가했다. 이 명령은 보존된 journal의 정확한 합성 가이드, 원본 이름/크기/키, 프레임 키, 철회된 운영 기록과 실제 저장 대상, 중지 상태를 확인한다. 개인 가이드나 변경된 입력은 거절하며 AI를 호출하지 않는다. 재실행 전 journal을 임의로 지우지 않는다.

복구 실행에서 `CLEANUP_ONLY_DONE`, `testGuideDeleted:true`, `aiHalted:true`, `aiCalls:0`을 확인했다. 원래의 가이드 삭제 로직으로 저장소 정리와 DB 삭제를 수행했고, 이후 시험 journal도 제거했다. 시험 이미지와 가이드/초안은 삭제되어 이 검사 결과를 편집 화면에서 다시 열 수 없다. 승인·철회 이력과 사용량 기록은 삭제하지 않았다.

최종 별도 읽기 전용 확인:

```text
reviewState: revoked
reviewVersion: 2
aiHalted: true
guideDeleted: true
journalRemoved: true
count: settled 1
generation: settled 1
health: 200
keyPrinted: false
```

최초 일괄 명령의 실패를 사후에 `PASS`로 바꾸지 않는다. **실호출·저장·철회 검증 성공 + 별도 정리 복구 성공**으로 기록한다.

## 운영 근거와 제한

- AI Studio SHOW ME의 무료 등급/결제 미설정을 09:21:23 UTC, 모델 한도 RPM 15 / 입력 TPM 250,000 / RPD 500을 09:21:33 UTC에 확인했다. 28일 최대 사용량을 잔여량으로 해석하지 않았다.
- Replit 월 추가 사용 예산 USD 0.02 / 알림 USD 0.01을 09:30:07 UTC에 읽었고 변경하지 않았다. 이는 계정의 포함 크레딧 초과분 한도이며 총비용 0 보장이 아니다.
- 프로젝트를 다른 곳에서 사용하지 않는다는 기존 사용자 확인을 이번 검사 범위에 적용했다. 다른 전송자를 기술적으로 차단한 결과는 아니다.
- 저장소는 `replit-policy-and-app-check`, `internalPermissionsVerified:false` 근거를 유지했다. 실제 IAM 전체를 직접 확인한 것으로 표시하지 않았다. [Replit App Storage 공식 설명](https://docs.replit.com/features/data-and-storage/object-storage).
- 회계용 보수적 가격은 [Google 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 표준 입력 USD 0.30/백만 토큰, 출력 USD 2.50/백만 토큰을 사용했다. 유료 이용 승인이 아니라 기존 `free_only` 계산 기준이다. 총 요청 제한은 계수 1회와 생성 1회를 합친 2회다.
- 새 키의 값을 브라우저·명령·로그·문서에 출력하지 않았다. 개인 영상, 마이크, 사용자 화면 녹화 또는 공개 공유는 사용하지 않았다.
