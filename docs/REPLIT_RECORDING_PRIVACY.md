# 녹화·비공개 전송 경계 — 2026-09-17

사용자 기준: **Replit 처리·저장은 허용. 원본 영상·추출 이미지·접근 키를 별도 서버, 외부 AI, 공개 공유로 보내지 않는다.**

이 변경은 앱 코드의 방어 보완이다. Replit 실환경 권한 감사, 브라우저/운영체제 전체 보안 감사, 유출 가능성 0% 보증이 아니다. 실제 개인 화면은 검사에 사용하지 않았다.

## 파일의 경로

1. 화면 선택은 브라우저 권한 창을 사용한다. 오디오는 요청하지 않으며 예상 밖 오디오 트랙도 거부한다.
2. 녹화 중 조각과 완료한 파일은 브라우저 메모리의 Blob/File로만 다룬다. 녹화 완료·파일 선택만으로 업로드하지 않는다. 녹화 코드에는 네트워크·영구 저장·다운로드 API가 없다.
3. 사용자가 **장면 추출 시작**을 눌러야 같은 앱 주소의 `/api/guides`로 원본을 전송한다. Replit에서는 기존 `/api` 프록시 → API Server → Replit App Storage를 사용한다. 서버는 처리 중 임시 로컬 사본도 사용한다.
4. 원본과 추출 화면은 Replit 저장소에, 메타데이터·편집 초안은 기존 DB에 보관한다. 기존 전체 작업 삭제와 미공개 초안 보관 만료 정리 절차를 유지했다. 메모리에서 참조를 지우는 것은 장치의 물리적 완전 삭제를 보장하지 않는다.

Replit App Storage 자체는 Google Cloud Storage 기반이다. 이는 Replit 저장 서비스의 기반 인프라이며 Gemini 등 외부 AI 전송과 다르다. [Replit 공식 App Storage 문서](https://docs.replit.com/features/data-and-storage/object-storage).

## 추가한 방어

- 업로드/상태/초안 저장/재시도/삭제를 모두 같은 출처(origin)로 제한한다. 환경 설정이나 복구 기록에 다른 호스트·포트·HTTP 강등·인증정보 포함 URL이 있으면 파일/키를 보내기 전에 거부한다. 복구 키를 임의로 삭제하지 않는다.
- XHR 업로드를 `fetch` + `redirect: error`로 변경했다. 응답 후 주소를 확인하는 방식으로는 이미 전송된 본문을 되돌릴 수 없기 때문이다. 같은 출처로의 리다이렉트도 거부한다. 재시도 요청에도 같은 제한을 적용한다. [RequestInit 공식 참조](https://developer.mozilla.org/en-US/docs/Web/API/RequestInit).
- Fetch에는 이 앱에서 쓸 수 있는 범용 업로드 진행 이벤트가 없어, 업로드 중 가짜 백분율 대신 서버 접수 응답을 기다린다고 표시한다. 영상 처리 단계의 서버 진행률은 유지한다.
- 프런트엔드 CSP로 연결·스크립트·이미지의 외부 주소를 제한하고, 외부 폰트 로드 및 선택적 Replit 개발 DOM/오류 브리지를 제거했다. React/Vite 개발 호환을 위해 인라인 스크립트·스타일 허용은 남아 있으므로 완전한 XSS 방어라고 주장하지 않는다. 호스팅 프록시가 별도로 주입하는 코드까지 제어한다는 뜻도 아니다.
- 추출 이미지/썸네일 URL은 해당 가이드·단계의 같은 출처 자산 경로인지 검사한다. 앱 API/이미지 응답은 `no-store`, `no-referrer`, `nosniff`, `Cross-Origin-Resource-Policy: same-origin`을 사용한다. 과거에 저장된 캐시나 이미 복사한 파일까지 소급 삭제하지는 않는다.
- 활성 업로드/처리/정리/시작·종료/작업 큐의 오류 로그는 이벤트·안전한 코드만 유지하고 SDK/FFmpeg/DB의 원문 예외 문자열을 출력하지 않는다. 호스팅 프록시·클라우드 사업자의 자체 로그는 별도다.
- AI admission의 기존 기본 비활성 상태를 유지한다. AI runner나 외부 provider를 앱 시작 경로에 연결하지 않았다. 이후 외부 AI 연동은 이번 허용 범위에 포함되지 않는다.

## 캡처 수명 관리

- 녹화 종료 버튼에서 MediaRecorder 종료 요청과 함께 **모든 MediaStreamTrack을 즉시 stop**한다. 비동기 `onstop`까지 캡처를 계속 유지하지 않는다. [MediaRecorder.stop](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop), [MediaStreamTrack.stop](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/stop).
- 취소·페이지 이탈·컴포넌트 해제·레코더 오류·크기 초과에서 캡처를 중단하고 조각/타이머/이벤트 참조를 정리한다. 늦게 도착한 화면 선택·종료 이벤트가 새 파일을 넘기지 못하게 세대 식별자로 차단한다.
- `녹화 취소·버리기`와 업로드 전 `선택한 영상 비우기`를 제공한다. 비우기는 선택된 메모리 참조를 버리는 동작이며 사용자의 원래 디스크 파일을 삭제하지 않는다.
- 정상 종료 후 마지막 데이터가 오지 않으면 3초 후 파일을 버리고 실패로 알린다. 빈 파일은 성공으로 처리하지 않는다. 브라우저 종료/OS 정지/프로세스 손상까지 앱 코드가 통제한다는 뜻은 아니다. 4분 제한도 브라우저 이벤트가 실행될 때 적용되며 실시간 OS 보장은 아니다.

### 최신 변경 — 2026-09-18 / 마지막 편집 저장부터 7일, 로컬 검증 완료

### 수정 전 보관·삭제 점검 — 2026-09-18

이번 점검은 로컬 코드·기존 단위검사·합성 재현과 공식 문서 확인에 한정했다. CDP/브라우저, 운영 DB/Storage, 개인 영상, 환경 비밀값에는 접근하지 않았다. 실제 프로젝트의 권한이나 사업자 백업을 직접 감사한 결과는 아니다.

## 원격 반영 승인 후 Replit 적용

1. 올바른 개발 브랜치와 깨끗한 작업 상태를 확인하고 `git pull --ff-only`.
2. `node scripts/run-tests.mjs` 및 기존 `PORT=20116 BASE_PATH=/ pnpm run build`로 검사한다. 실패 검사를 건너뛰거나 FFmpeg 버전 검증을 낮추지 않는다.

4. 같은 출처가 아닌 과거 `VITE_SHOWME_PROCESSOR_URL` 설정은 이제 차단된다. Replit에서는 같은 앱의 `/api` 프록시를 사용한다. 잘못된 복구 주소를 무시하며 다른 곳으로 키를 보내거나 복구 기록을 자동 삭제하지 않는다.

main 병합·Publish·실제 파일 전송·저장소 권한 변경은 이 로컬 검증에 포함되지 않는다.
