# Replit 이관 안전장치·테스트 복구 — 1–2단계

기준: `f8844eb` / `codex/replit-migration-checkpoint`, 작업일: 2026-09-16.

## 변경 범위

- `scripts/post-merge.sh`에서 scaffold DB의 `push` 호출을 제거했다. 기존 잠금 파일 기반 의존성 설치는 유지한다. 실제 ShowMe SQL migration이나 서버 시작 코드는 바꾸지 않는다.
- `.gitignore`에서 실제 환경 파일·인증 키·로컬 영상/프레임 데이터·도구 상태 제외를 복구했다. `.env.example`은 추적 가능하게 유지한다. 이미 추적 중인 파일은 삭제하거나 추적 해제하지 않는다.
- `.gitattributes`에서 셸 스크립트를 LF로 고정했다. Windows에서 편집 후 Linux의 후처리 실행이 깨지는 것을 방지한다.
- `test:migration`을 추가했다. Node와 Git만 사용하는 읽기 전용 회귀 검사다. 서버 import, `.env` 로딩, 의존성 설치, 후처리 실행, DB/Storage/Gemini 접속은 하지 않는다.

## 1단계 검증 기록

1단계 당시에는 저장소 루트에서 `node --test scripts/tests/migration-safety.test.mjs`를 실행했다. 현재 전체 안전 검사는 `node scripts/run-tests.mjs migration` 또는 `pnpm run test:migration`으로 실행한다. 당시 이 PC의 번들 pnpm 실행기는 설치를 자동 시도했으나 네트워크 권한 오류로 진행되지 않아 중단했고 직접 Node 실행으로 검증했다. 후속 Linux 검증은 아래 2단계 기록을 따른다.

검사 범위: 후처리 명령 제한, 위험 명령 삽입 시 검사 실패, 셸 줄바꿈, 테스트 명령 연결, 가상 비밀/출력 경로의 추적 제외, 예시/소스/SQL 경로의 추적 허용, 기존 미디어 보안 검사 유지, 실제 실행 위치의 과거 SQL/메타데이터 보존. 새 migration 추가는 허용하되 과거 journal 항목의 변경/삭제는 허용하지 않는다.

기존 의존성 설치나 서버 시작을 실행한 검증은 아니다. 이미 추적된 비밀정보를 지우는 기능도 아니며, 비밀정보 전체 감사와 구별한다.

검증 기록: Node 24.15.0 / Windows에서 변경 전 검사 실패로 누락을 재현했고, 보완 후 **42개 통과 / 실패 0 / 생략 0**을 확인했다. 셸 스크립트의 `bash -n` 구문 검사와 `git diff --check`도 통과했다. Replit/Linux에서의 후처리 실제 실행이나 전체 제품 빌드는 이번 범위가 아니다.

## 1단계 당시 다음 순서

1. 보존된 서버 단위 테스트 36개 파일·보조 자료와 클라이언트 테스트를 현재 `artifacts/` 소스를 대상으로 복구한다. 백업 소스에 대한 검사로 대체하지 않는다.
2. 테스트 경로·스크립트·개발 의존성과 별도 PostgreSQL 시험 경계를 복구하고 타입/빌드/기능 회귀 검사를 수행한다.
3. 현 잠금 파일에는 Linux 전용 네이티브 의존성 제외 설정이 있다. Windows 기존 프로젝트에 무작정 설치하지 말고 독립 환경에서 검증한다.

이번 단계에는 Replit 파일 직접 변경, main 병합, Publish, 실제 DB 변경, 저장소/Gemini 호출 또는 자동 분석 활성화가 포함되지 않는다. 로컬 보완본은 Replit에 별도로 반영해야 한다.

## 2단계 완료 — 2026-09-16

- 백업의 서버 테스트 36개 파일·보조 자료와 클라이언트 테스트를 실제 `artifacts/` 소스로 연결했다. PostgreSQL 통합 검사도 활성 코드 경로로 복구했지만 기본 실행과 분리했다.
- 그룹별/전체 테스트 실행기, 직접 테스트 의존성, 엄격한 테스트 타입 검사와 잠금 파일을 복구했다. 비밀 환경·Node 사전 로딩 옵션은 자식 프로세스에서 제외한다.
- `/api/healthz`의 준비 전 503→완료 후 200, 실행 위치별 SQL 폴더 선택, 테스트 복구 누락, 환경 제외, 미디어 도구 선택을 추가 검사한다. SQL 자체나 DB 스키마는 변경하지 않았다.
- 기존 합성 이미지의 JPEG 바이트가 OS/도구에 따라 달라져 승인 지문 비교가 실패했다. 원래 Windows 코드에서 역사적 전체 요청 지문 일치를 확인한 두 이미지를 고정했다. 참조 지문·전송 승인 조건은 변경하지 않았다. 합성 자료는 이제 설치 스크립트나 FFmpeg에 의존하지 않으며 해시 검증과 버퍼 독립성 검사도 한다.
- 기본 480개에 이관 회귀 7개와 안전 검사 49개를 더해 **536개 통과 / 실패 0 / 생략 0**이다: 서버 483, 클라이언트 4, 안전장치 49.
- 전체 패키지 타입 검사(복구된 테스트 포함), API·ShowMe·mockup 빌드, 잠금 파일 오프라인 고정 설치, 셸/실행기 구문과 Git 공백 검사도 통과했다.

환경: 공식 Node `24.15.0-bookworm-slim` 이미지(`sha256:4e6b70dd6cbfc88c8157ba19aa3d9f9cce6ba4703576d55459e45efcbc9c5f5d`), pnpm 10.17.1. 의존성 준비 후 컨테이너 네트워크를 분리해 검사했다. 운영 설정/키, 실제 DB/Storage/Google은 사용하지 않았다. 임시 환경에 고정 개발 패키지의 FFmpeg 설치만 명시적으로 수행했으며, 프로젝트의 pnpm 설치 스크립트 허용 목록은 변경하지 않았다.

합성 영상은 Linux 번들 FFmpeg 7.0.2 / FFprobe 4.0.2로 검증했다. 오래된 기본 FFmpeg 5.1.9로 실행한 최초 회전 영상 검사는 실패했으며, 위 536개는 도구 준비와 고정 이미지 보완 후 전체 재실행 결과다. 이는 Replit 운영용 8.1.2의 실환경 검사 대체가 아니다. 기존 운영 미디어 보안 기준은 그대로다.

남은 경고: ShowMe UI 세 파일의 소스맵 위치 경고와 API 번들 크기 안내가 있으나 빌드는 종료 코드 0이다. 별도 PostgreSQL 43개·Replit 브라우저 실사용·운영 보안/배포는 이번에 재검증하지 않았다.

실행 방법과 경계는 [테스트 안내](TESTING.md)에 기록했다. 전체 로컬 로그는 Git 제외 경로 `outputs/migration-verification/tests-linux.log`, `build-linux.log`에 있다. 2단계 종료 시점에는 GitHub/Replit에 반영하지 않았으며 후속 순서는 변경 리뷰·체크포인트 반영 후 Replit 합성 영상 실환경 검증이다.

## 3단계 변경 리뷰 — 2026-09-16

- 기능 코드는 위 Linux 검증본에서 변경하지 않았다. 테스트 경로 변환 외 변경이 있는 기존 파일은 준비 상태 검사, 버퍼 독립성 검사, 미디어 도구 선택을 추가한 5개이며 원래 검사를 삭제하지 않았다.
- 안전 검사 49개, 실행기 구문 및 Git 공백 검사를 다시 통과했다. 전체 536개/타입/빌드 결과는 위 2단계의 동일 기능 코드 검증 기록이다. 이 단계에서 전체 실행을 새로 했다고 계산하지 않는다.
- DB 후처리 차단, 운영 미디어 버전 검사, 과거 합성 요청 지문과 전송 승인 조건을 유지했다. 이번 리뷰에서 업로드를 막을 추가 결함은 확인하지 못했다. 이는 전체 제품 보안 인증이나 운영 승인이라는 뜻이 아니다.
- `codex/replit-migration-hardening`을 별도 보관 브랜치로 사용한다. `main` 및 기존 `codex/replit-migration-checkpoint`는 변경하지 않는다.
- Replit의 사용자 변경부터 확인하고 가져오기·재검증을 진행한다. [반영 순서](REPLIT_UPDATE.md)를 따르며, 원격 업로드 성공 여부는 실제 원격 커밋 확인으로 판정한다.
