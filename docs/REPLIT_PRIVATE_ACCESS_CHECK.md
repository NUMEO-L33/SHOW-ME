# 합성 영상 자동 접근 검사

이 도구는 **고정된 합성 영상 하나로만** 시험 가이드를 생성하고, 편집 키 없는 접근/잘못된 키의 접근이 거부되는지 검사한 뒤 자신이 만든 가이드를 삭제한다. 실제 개인 영상, 화면 녹화, 기존 가이드 ID, 기존 편집 키는 입력받지 않는다. AI 분석·공개 게시·권한 변경을 호출하지 않는다.

## 범위

- 내장 영상: 단색 화면, H.264 160×90, 1초/5프레임, 음성 없음, 1,785 bytes. 실행 때 SHA-256을 검사한다. 원본 파일 선택이나 외부 다운로드가 없다.
- 정상 편집 키로 가이드·초안 조회 및 서명된 프레임/썸네일 조회가 성공해야 한다.
- 같은 **실제로 존재하는** 가이드·초안·서명 없는 이미지 경로에 키가 없거나 잘못된 키가 있으면 앱의 404 오류만 반환해야 한다. 200 HTML 로그인 화면이나 내용을 포함한 404는 통과가 아니다.
- 부정 접근 검사 전후에 정상 조회를 다시 확인한다. 존재하지 않는 ID의 404를 성공으로 세지 않는다.
- 시험 가이드의 DELETE 204와 그 뒤 가이드·초안·기존 서명 이미지 조회 거부를 확인한다. 정상 실행에서는 원본·추출 이미지 삭제 API가 완료된 뒤에만 PASS가 나온다.
- 업로드 POST는 한 번만 보낸다. 모든 요청은 지정한 주소에 한정하며 리다이렉트를 따라가지 않는다. 응답 본문 크기/요청/전체 검사/정리 대기 시간은 제한된다.

이 검사는 **Node에서 직접 보낸 API 요청**이다. 기본값인 로컬 API 주소 검사로 브라우저의 녹화 중 무전송, 브라우저 업로드 POST 목적지, 실제 HTTPS 프록시/CSP, 기존 WebSocket, 저장소 IAM/DB 권한, 사업자 백업 삭제까지 확인한 것으로 취급하지 않는다. HTTPS 주소를 지정해도 브라우저 검사가 되지는 않는다.

## Replit에서 실행

검사 파일이 Replit 작업본에 반영된 뒤, 기존 API Server가 준비된 상태에서 Shell에 한 번 실행한다. 서버를 새로 띄우거나 재시작하는 명령은 아니다.

```sh
node scripts/check-private-access.mjs --run-synthetic
```

기본 목적지는 `http://127.0.0.1:8080`이다. Replit 안에서 이 API가 이미 Replit Storage/PostgreSQL로 동작하고 있다면 작은 시험 가이드와 파일이 **실제 해당 서버/저장소에 만들어진다**. 사용료가 절대 0이라고 보장하지 않으며, 개발 환경에서 한 번 실행하는 진단이다.

외부 경유 API 주소도 검사해야 할 때만 현재 소유한 ShowMe 앱의 HTTPS origin을 명시한다. 아래 주소는 자리표시자다.

```sh
node scripts/check-private-access.mjs --run-synthetic --origin https://YOUR-APP.replit.dev
```

허용 목적지는 명시적인 loopback 주소 또는 HTTPS `*.replit.dev`/`*.replit.app` origin뿐이다. 경로·쿼리·로그인정보가 들어간 URL이나 다른 도메인은 거부한다. 외부 주소 자동 탐색은 하지 않는다. 인수 없이 실행하면 검사/전송을 하지 않으며, 설명만 보려면 `--help`를 사용한다.

성공 출력의 마지막 부분:

```text
PRIVATE_ACCESS_CHECK NO_KEY_AND_WRONG_KEY_DENIED
PRIVATE_ACCESS_CHECK TEST_GUIDE_DELETED
PRIVATE_ACCESS_CHECK PASS
```

`PASS`는 이 API 검사와 해당 실행의 삭제 확인이 끝났다는 뜻이다. 전체 제품 보안 감사 완료 선언이 아니다. 삭제가 되더라도 앞선 접근 검사에 실패했으면 종료 코드는 1이며 PASS를 출력하지 않는다.

## 중단 및 삭제 실패

업로드 응답이 끊겨도 자기 시험 작업을 정리할 수 있도록, 전송 전에 새로 만든 가이드 ID·편집 키·목적지를 `.private-access-check/run.json`에 저장한다. 기존 앱/브라우저의 편집 키는 읽지 않는다. 이 폴더는 Git에서 제외하며 새 Unix 디렉터리/파일 권한은 각각 0700/0600이다. Windows에서는 OS 계정/디렉터리 ACL에도 의존한다. **복구 파일을 채팅·GitHub·HAR 등에 올리지 않는다.**

- 정상 정리 확인 후 그 실행의 복구 파일만 삭제한다. 저장소 전체, 다른 가이드 또는 사용자가 고른 파일을 삭제하지 않는다.
- 삭제 202/409/503 또는 일시 통신 오류는 제한된 횟수로만 재확인한다. 404 단독, 대기 만료, 상태 불일치, 삭제 응답 유실은 정리 완료로 간주하지 않는다. 실패/불확실이면 복구 파일이 남고 PASS는 나오지 않는다.
- Ctrl-C 한 번은 검사 중단 후 정리를 시도한다. 두 번째 중단·프로세스 강제 종료·컴퓨터 종료까지 삭제를 보장하지 않는다.
- 이전 복구 파일이 있으면 새 시험 업로드를 시작하지 않는다. 검사 프로세스가 끝난 뒤 다음 명령은 **기존 시험 가이드의 삭제만** 시도한다.

```sh
node scripts/check-private-access.mjs --cleanup-only
```

복구 완료는 `TEST_GUIDE_DELETED`, `CLEANUP_ONLY_DONE`으로 표시한다. 이전에 실패한 접근 검사가 통과한 것으로 바꾸지 않는다. 다른 검사 프로세스가 살아 있으면 거부한다. PID 재사용/파일 손상/권한 문제도 보수적으로 실패할 수 있으므로 다른 프로세스를 강제 종료하거나 복구 파일을 지워 문제를 숨기지 않는다. 동시에 여러 창에서 실행하지 않는다.

아주 이른 업로드 취소는 서버의 취소 기록으로 남을 수 있다. API가 이를 204로 응답해도 가이드 조회가 계속 가능하면 이 도구는 `CLEANUP_UNCONFIRMED`로 남긴다. 실제 파일 잔존 여부/서버 보관 정책을 따로 확인해야 하며 임의로 삭제 완료 처리하지 않는다.

## 로컬 검증 기록 — 2026-09-18

- 진단 단위/실제 loopback HTTP/CLI 검사 26개 통과: 목적지 제한, 동의 인수, 잘못된 접근 허용 탐지, 존재하지 않는 가이드의 거짓 통과 방지, 본문 정체/크기 제한, 업로드 307 추적 금지, 응답 유실, 정리 실패/복구, 민감한 응답·키 비출력을 검사했다.
- 실제 HTTP + FFmpeg + LocalStorage/JSON 통합 검사 2개 통과: 내장 영상을 실제 처리하고 원본·프레임·썸네일이 저장됐다가 삭제되는 것을 확인했다. 권한을 일부러 잘못 허용한 경우 실패하면서도 시험 자료를 삭제했다. 분석 API 요청은 0이었다.
- 새 테스트 TypeScript 검사 및 진단 스크립트 구문 검사 통과. `node scripts/run-tests.mjs`의 일반 전체 회귀(migration → server → client)도 종료 코드 0으로 통과했다. 로컬 Windows의 기존 FFmpeg/FFprobe 경로만 테스트 환경에 지정했으며 Replit의 바이너리/설정은 바꾸지 않았다.
- 실제 Replit에는 아직 이 자동검사를 실행하지 않았다. 이 파일을 추가하는 것만으로 배포/기동/클라우드 전송이 실행되지 않는다.
