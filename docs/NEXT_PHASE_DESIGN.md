# ShowMe — 기능별 상세 설계 v1

작성일: 2026-09-12 · 갱신일: 2026-09-14 · 상태: 순차 구현 기준 설계 · 현재 구현 기준: `317f9bf`

전체 범위·실행 순서·승인 지점은 [전체 개발 계획](DEVELOPMENT_PLAN.md)이 기준이고, 이 문서는 각 기능의 데이터 계약·실패 처리·완료 기준을 상세화한다. AI 큐·비용의 추가 계약은 [AI 실행 설계](ANALYSIS_EXECUTION_DESIGN.md)를 따른다. **설계는 구현·실서비스 검증·배포 완료를 뜻하지 않는다.** 실제 완료 기록은 [구현 게이트](IMPLEMENTATION_PHASES.md)에서 관리한다.

## 1. 제품 범위와 전제

입력은 **화면을 녹화한 영상**, 기본 결과는 **따라 하기 쉬운 한국어 단계별 가이드 링크**다. 녹화 영상 자체를 자동 편집한 새 동영상으로 내보내는 기능은 이번 범위가 아니다. 원본 영상 보기 옵션은 별도로 설계한다.

- 만든 사람: 반복해서 설명하는 가족·동료·직원. 받는 사람: 새로운 디지털 절차가 낯선 한국어 사용자.
- 휴대전화 세로 녹화와 PC 가로 녹화를 모두 다룬다. 받는 사람은 앱 설치·로그인 없이 링크를 연다.
- 직접 녹화는 현재의 지원 여부 확인과 파일 업로드 대체 경로를 유지한다. 모든 휴대전화 브라우저에서 직접 녹화가 된다고 약속하지 않는다.
- 직접 녹화 4분/64 MiB, 파일 업로드 500 MiB와 현재 서버 영상 제한을 유지한다. 직접 녹화의 오디오는 계속 수집하지 않는다.
- 로그인·결제·팀 기능·음성 내레이션·AI 편집 명령·완성 영상 내보내기는 추가하지 않는다.
- 원안의 GPT-4o는 초기 후보였으며, 2026-09-12 사용자 선택에 따라 첫 공급자를 Gemini로 변경했다. 공급자 교체 가능한 구조, 0–100% 좌표, 직접 조작 편집은 유지한다. 일반 어댑터 기본값은 `gemini-3.8-flash`이며 자동 교체하지 않는다. 2026-09-14 사용자 승인으로 `gemini-3.5-flash-lite`를 명시적 시험 옵션에 추가했고 실제 가상 화면 분석에 성공했다. 후속 분석 API의 모델 정보는 3.5로 명시했지만 운영 실행은 아직 꺼져 있다. [구현 범위](GEMINI_SETUP.md).
- 기존 Sites 화면 + 독립 미디어 서버 + PostgreSQL + Replit App Storage를 유지한다. 새 D1/R2 저장소를 병행해서 만들지 않는다.

### 현재 상태를 읽는 법

Gate 0–2, Gate 3A, 3B-1 가상 화면 연결, 3B-2A HTTP 경계는 코드·로컬 검증 체크포인트다. 기준 커밋에서 테스트 175개와 타입·린트·빌드가 통과했다. 실제 AI 자동 접수는 꺼져 있다. 실제 녹화 권한·브라우저 전체 흐름·PostgreSQL/저장소 장애 복구·운영 배포는 남아 있다. 현재 공개 사이트는 이전 프로토타입이다.

## 2. 전체 순서와 단계 경계

```text
직접 녹화 / 파일 선택
  → 안전한 업로드·프레임 추출
  → AI 처리 동의·분석 → 한국어 초안과 확인할 항목
  → 작성자 검토·수정·서버 저장
  → 개인정보 확인·공유용 이미지 생성
  → 확정된 게시본을 링크로 공유
```

| 순서 | 작업 묶음 | 이번 단계의 결과 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|
| 0 | Gate 2 보완 검증 | 녹화·업로드 실제 동작 기록 | 지원 브라우저에서 녹화→업로드→프레임 확인, 취소·삭제 확인 |
| 1 | Gate 3: AI 초안 | 설명·클릭 후보·개인정보 후보가 있는 비공개 초안 | 계약·실패 복구 테스트 + 합성 화면 품질 검증 |
| 2 | Gate 4: 저장되는 편집기 | 새로고침해도 남는 수정 결과 | 저장 충돌·좌표·병합·재생성·키보드 조작 검증 |
| 3 | Gate 5: 개인정보와 게시 | 픽셀에 가림을 적용한 독립 게시본 | 미가림 자산 노출 차단·게시 경합·철회 테스트 |
| 4 | Gate 6: 링크와 뷰어 | 로그인 없이 보는 모바일/PC 가이드 | 외부 수신자 접근·확대·이동·공유 미리보기 확인 |
| 5 | Gate 7: 배포와 사용자 검증 | 제한된 실제 사용자 시험판 | 실제 저장소/DB·배포 복구·전체 흐름 검증 |

각 묶음은 **설계 확인 → 구현 → 자동 검사 → 해당 기능 수동 확인 → 리뷰 → 체크포인트**로 끝낸다. 검사가 실패하면 같은 묶음에서 해결한다. 빌드를 여러 번 실행하는 것은 정상적인 검증 과정이지만, 빌드 성공만으로 다음 기능까지 완료 처리하지 않는다. 로컬 완료와 운영 완료를 별도 표시한다.

Gate 2 보완의 브라우저 권한 확인에 사용자 참여가 필요하면 해당 항목을 미검증으로 남긴다. AI 계약·테스트 설계는 진행할 수 있으나, 실제 제품 전체가 통과했다고 표시하지 않는다. 공개 Sites를 먼저 덮어쓰지 않는다.

## 3. 공통 구조: 상태·권한·데이터

### 3.1 상태를 네 가지로 나눈다

기존 `Guide.status`는 **미디어 처리 상태**로 유지한다. `ready`는 화면 추출 완료이며 AI 완료·게시 완료를 뜻하지 않는다. 새 상태는 별도로 추가한다.

| 영역 | 제안 상태 | 중요한 규칙 |
|---|---|---|
| 미디어 | 기존 uploading/queued/probing/extracting/ready/failed | AI 실패로 ready 프레임을 삭제하거나 재추출하지 않음 |
| AI 분석 | not_requested/queued/running/succeeded/failed/cancelled | 분석 실행 ID·시도 번호·입력 버전에 귀속 |
| 편집 | draftRevision + 저장 상태 | 화면의 ‘저장됨’은 서버 확인 이후에만 표시 |
| 게시 | unpublished/publishing/published/revoked | 게시 중 실패해도 기존 게시본은 유지 |

전체 삭제는 모든 영역보다 우선한다. 기존 삭제 표식·소유권 검사를 유지하고, AI/게시 작업에도 취소·늦은 응답 무효화·늦은 자산 정리를 확장한다. AI 작업이 미디어 worker의 `processingAttemptId`를 재사용하지 않게 한다.

### 3.2 최소 데이터 추가안

기존 `guides`, `guide_steps`를 유지한다. 프레임과 시각 정보는 기존 단계 기록을 참조하고, 편집 상태는 별도로 저장한다. **`guide_drafts`와 `analysis_runs`는 Gate 3A에서 이미 추가했다.** 아래에 현재 상태와 추가 설계를 구분한다.

| 저장 대상 | 핵심 필드와 역할 |
|---|---|
| `guide_drafts` (현재) | guideId, revision, inputFingerprint, document, createdAt/updatedAt. schemaVersion은 document 안에 있음. 별도 expiresAt·개인정보 확인 이력은 후속 추가 |
| `analysis_runs` (현재) | guideId/id 복합 키, status, payload에 입력 지문·manifest·기준 revision·동의·provider/model/prompt·lease·시도·오류·사용량. 큐 인덱스·묶음·예산은 후속 추가 |
| 분석 결과 (현재) | runId에 귀속된 검증된 제안. step/frame ID와 설명·클릭 후보·개인정보 후보만 보관; 이미지 base64·전체 OCR 원문·원본 API 응답은 저장하지 않음 |
| `publication_jobs` | 게시 요청 ID, guideId, 요청 revision, 작업 소유권·진행 상태·오류. 반복 클릭/재시작 후 같은 요청 추적 |
| `guide_publications` | publicationId, guideId, sourceDraftRevision, 상태, 확정 문구·정렬·공개 자산 참조, publishedAt, originalSharingEnabled |
| `guide_assets` | assetId, guideId, 소유 작업 ID, 용도·private object key·생성/삭제 상태. 늦은 쓰기와 고아 자산의 정리 목록 |
| 가이드의 게시 참조 | activePublicationId, 공개 slug. 공개 응답은 이 참조가 가리키는 확정본만 읽음 |

`document` 안의 편집 단계는 안정적인 ID, sourceStepIds, activeFrameStepId, 짧은 제목, 설명, elements, review 상태를 가진다. 병합해도 원본 프레임 기록은 지우지 않는다. 모든 사용자 수정은 증가하는 정수 revision으로 비교한다. 미디어 heartbeat용 `updatedAt`을 편집 충돌 버전으로 쓰지 않는다.

새 object key를 만들기 **전에** 자산의 정리 소유권을 기록한다. 기존 `guideAssetKeys()`가 아는 미디어 키에 더해 새 자산 목록을 삭제 처리에 통합한다. 새 표식·작업·자산이 남아 있으면 가이드의 최종 삭제를 완료하지 않는다. PostgreSQL과 로컬 JSON 구현 모두 같은 계약 테스트를 통과해야 한다.

### 3.3 좌표와 권한 계약

- 좌표 기준은 회전 보정된 **대표 프레임 전체**다. 컨테이너의 빈 여백·확대 배율이 포함된 좌표를 저장하지 않는다.
- 점: 유한한 x/y, 0–100. 사각형: 양수 width/height, x+width≤100, y+height≤100. AI의 범위 밖 값은 조용히 보정하지 않고 오류/확인 대상으로 처리한다.
- 가림 영역은 frame ID에 묶는다. 다른 프레임으로 교체하면 이전 프레임의 좌표를 그대로 적용하지 않고 다시 확인한다.
- 편집·재생성·게시·철회·삭제는 기존 edit token 인증을 요구한다. 키는 요청 헤더에만 전달하고 서버 URL query에 넣지 않는다.
- 공개 slug는 편집 키와 독립적이며 추측하기 어려운 난수로 만든다. ‘링크를 아는 사람에게 공유’이지 수신자별 접근 통제는 아니다.
- 복구/다른 기기 편집 링크가 필요하면 별도 편집 경로의 URL fragment를 최초 1회 읽고 주소에서 제거하는 방식을 검토한다. 기존 브라우저 키 저장과 함께 XSS 위험이 있으므로 편집 화면의 외부 스크립트·분석 도구를 제한한다. 서버 정본을 브라우저 저장으로 대체하지 않는다.

## 4. 순서 0 — 녹화·업로드 보완 검증

입력 기능을 다시 만드는 단계가 아니라 현재 기능의 남은 실제 확인이다. 개인정보 없는 합성 화면으로 시작한다.

1. 지원 대상으로 정한 데스크톱 브라우저에서 창/탭/전체 화면 선택, 권한 취소, 브라우저의 공유 종료, 4분 종료를 확인한다.
2. 생성 파일이 업로드 입력으로 전달되고, 원래 방향·비율의 프레임이 표시되는지 확인한다. 소리가 수집되지 않는지도 확인한다.
3. 파일 업로드는 MP4/MOV/WebM, 휴대전화 세로/PC 가로/회전 영상을 확인한다. 직접 녹화 미지원 환경은 OS 녹화 파일 업로드를 안내한다.
4. 업로드 중 취소, 응답 유실 후 새로고침, 다른 탭의 작업 복구, 삭제 후 재접근을 확인한다.
5. 브라우저·버전·입력 방식·결과를 기록한다. 자동화 도구의 파일 선택 실패와 앱의 업로드 실패를 구분한다.

완료 기준: 대표 입력 경로의 실제 성공과 실패 기록이 있으며, P1 데이터 유실/권한/삭제 문제가 없다. 실제 PostgreSQL·App Storage 검증은 Gate 7에도 반복한다.

## 5. 순서 1 — Gate 3 AI 초안

### 5.1 사용 흐름과 외부 전송

최초 분석 전 ‘선택된 화면 이미지를 외부 AI에 보내 설명과 개인정보 후보를 생성함’을 명확히 안내하고 동의받는다. 원본 영상 전체·오디오·편집 키·자산 티켓은 AI에 보내지 않는다. 동의하지 않으면 미디어 결과를 보존하며 분석을 시작하지 않는다. 처음 시험은 합성 데이터로 한다.

대표 프레임은 서버가 비공개 저장소에서 읽어 크기 제한된 이미지 입력으로 보낸다. 공급자가 접근할 공개 원본 URL을 만들지 않는다. 2026-09-12 가상 화면 진단 성공을 근거로 Gemini `generateContent` API의 인라인 이미지와 구조화 출력을 사용한다. 공급자용 schema는 단순화하되 서버의 길이·개수·좌표·추가 필드 검증은 유지한다. [공식 API](https://ai.google.dev/api/generate-content), [구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output). 현재 로컬 시험 명령은 비공개 저장소의 실제 프레임 대신 코드로 만든 가상 화면만 전송한다.

애플리케이션 자체 작업 큐를 계획하며 외부 도구 호출은 제공하지 않는다. `generateContent`에는 Interactions용 `store` 옵션을 보내지 않으며 **무보관·학습 제외를 보장하지 않는다.** 현재 어댑터는 별도 thinking 설정 없이 출력 8192토큰·60초 상한을 유지한다. Gemini 무료 등급 시험은 개인정보 없는 가상 화면으로만 진행한다. 실제 사용자 화면은 적합한 데이터 처리 조건·동의 절차를 정하기 전까지 전송하지 않는다. ShowMe에서 삭제해도 이미 전송한 공급자 데이터가 동시에 모두 삭제된다고 약속하지 않는다. [Google 이용약관](https://ai.google.dev/gemini-api/terms).

### 5.2 분석 입력과 출력

- 공급자 인터페이스: `analyzeFrames(input, signal)`로 시작한다. 첫 어댑터만 구현하고 두 번째 공급자의 실제 연동은 보류한다.
- 최초 모델 `gemini-3.8-flash`의 CLI는 HTTP 503으로 실패했다. 이후 사용자 승인을 받은 `gemini-3.5-flash-lite` 시험에서는 동일한 가상 화면 2장으로 한국어 설명·버튼 좌표·결과 저장까지 성공했다. 다양한 화면 품질·장기 가용성은 아직 미검증이며, 시험 성공을 기본 모델의 자동 교체로 처리하지 않는다. [Gemini 3.5 Flash-Lite 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite).
- 기존 최대 24개 대표 프레임을 시간순으로 사용한다. 초깃값 제안: 요청당 분석 대상 4장 + 앞뒤 문맥 각 1장 이내. 총 6묶음 이내이며 반복되는 문맥 이미지도 비용 계산에 포함한다.
- 각 이미지에 서버가 정한 frame/step ID·타임스탬프·방향·역할을 붙인다. 문맥 프레임의 개인정보 결과를 다른 대표 프레임에 적용하지 않는다.
- 출력: 짧은 한국어 단계명, 설명, 행동 종류(tap/wait/observe/unknown), 클릭 후보 또는 null, 개인정보 후보 배열, 확인 필요 사유, 인접 중복 단계 제안.
- 개인정보 후보는 종류·영역·frame ID만 반환하도록 유도한다. 전화번호·계좌번호 같은 실제 값을 설명이나 로그에 반복하지 않는다.
- 제목·설명은 일반 텍스트이며 HTML/임의 URL·실행 명령을 결과 계약으로 허용하지 않는다. 화면 안의 ‘이전 지시를 무시하라’ 같은 문구는 관찰 데이터이지 명령이 아니다.
- 한 프레임으로 클릭을 확정할 수 없으면 null과 ‘확인 필요’를 반환한다. 현재 녹화 코드는 별도 클릭 이벤트를 수집하지 않으므로 정확한 클릭 관측으로 표시하지 않는다. 기존 중앙 50/50 임시 포인터는 실제 AI 모드에서 제거한다.
- 현재 프레임들로 절차가 불명확하면 그 한계를 표시한다. 추가 시점 프레임 추출은 품질 검증에서 필요한 경우에만 별도 소단계로 추가한다.

한국어 작은 글씨와 정밀 위치 추정은 별도 평가가 필요하다. 모델의 자기평가를 정확도 확률로 표시하지 않는다. [Vision 한계](https://developers.openai.com/api/docs/guides/images-vision#limitations).

### 5.3 실행·실패·비용

- `runId + inputFingerprint + baseDraftRevision`을 기록하고, 작업당 하나의 실행만 소유권을 얻는다. 동일 재요청은 같은 실행 상태를 돌려준다.
- 다음 항목은 목표 동작이며, 현재 내부 실행기는 성공 묶음을 메모리에만 모은다. [AI 실행·운영 예산 설계](ANALYSIS_EXECUTION_DESIGN.md)에 저장 계약·원자 예약·정산·재시작·자정 처리와 구현 순서를 정했다.
- 분석 큐는 미디어 큐와 실행 슬롯을 분리한다. AI 대기가 영상 처리·삭제 worker를 막지 않는다.
- 초깃값 제안: 요청 제한 60초, 전체 실행 180초, 묶음당 일시 오류 재시도 1회, 가이드 내 동시 분석 1개. 값은 설정에 모으고 품질/지연 측정 후 조정한다.
- SDK 자동 재시도와 앱 재시도를 중복 적용하지 않는다. 429·인증 오류·거절·잘못된 입력은 자동 재시도하지 않는다. 일부 일시적 5xx만 남은 시간·예산·영속 전송 횟수 안에서 재시도한다. 묶음 dispatcher가 재시도를 소유하면 어댑터 내부 재시도는 0으로 둔다.
- 유효 JSON 외에도 단계 ID의 소속·누락·중복, 길이, 좌표, 사각형 끝점, 응답 완료 여부를 서버에서 검증한다. 거절/불완전 응답은 성공으로 취급하지 않는다. [거절 처리 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs#refusals-with-structured-outputs).
- 일부 묶음 실패 시 성공한 제안은 보존하고 실패 범위를 표시한다. 전체 분석 완료로 표시하지 않는다. 재시도는 실패 묶음만 대상으로 한다.
- AI가 실패해도 원본·프레임·기존 초안은 유지한다. 취소·전체 삭제·입력 버전 교체 후 늦게 도착한 응답은 적용하지 않는다.
- 최초 결과는 초안이 미수정 상태이며 기준 revision이 일치할 때만 초기 초안으로 채택한다. 사람이 수정한 내용은 자동 덮어쓰지 않는다. 재생성은 제안으로 저장하고 ‘적용’할 때 다시 revision을 검사한다.
- 이미지 수·요청 크기·출력 토큰·실제 사용량·요청 횟수에 상한을 둔다. 일일 전체 예산과 익명 접근의 사용 제한도 서버에서 집행한다. edit token만으로 비용 남용을 막는다고 보지 않는다.
- 모델별 비용 설정을 근거로 호출 전에 최대 사용분을 예약하고 결과 사용량으로 정산한다. 결제 금액이 불명확한 timeout 호출은 보수적으로 예약을 유지한다. 실제 단가·가이드 예산은 실호출 전 확정하며 이번 문서에서 비용을 단정하지 않는다.
- 로그는 내부 작업 ID·오류 코드·지연·토큰 수 중심으로 남긴다. 프롬프트 원문·영상 이름·개인정보 값·이미지·인증 헤더는 남기지 않는다.

### 5.4 제안 API와 구현 묶음

기존 업로드/조회/재시도/삭제 API는 유지한다. 다음은 추가 계약이다.

2026-09-14 구현 상태: **Gate 3B-2A에서 아래 세 HTTP 경로를 등록**했다. 인증·동의 형식·중복·조회·취소는 로컬 테스트로 검증했으나, 시작 코드에 내구성 있는 AI 접수기·예산 연결이 없어 새 분석은 503으로 거절한다. 아래 표는 목표 계약이며, 현재 응답 필드와 제한은 [분석 API 문서](ANALYSIS_API.md)가 기준이다. 제품 내 동의·큐·운영 예산·복구·재시도 안내는 후속 단계다.

| API | 역할 |
|---|---|
| `POST /api/guides/:id/analysis` | 인증·동의·미디어 ready·예산 검사 후 202와 runId 반환 |
| `GET /api/guides/:id/analysis/:runId` | 진행 상태·검증된 제안·오류·재시도 가능 여부 반환 |
| `POST /api/guides/:id/analysis/:runId/cancel` | 분석만 취소. 전체 가이드 삭제와 구분 |

3A: 계약·추가 스키마·revision·가짜 공급자·삭제 통합 테스트 → 3B: 실제 공급자·큐·예산·복구 → 3C: 진행/실패/확인 필요 화면 및 합성 자료 품질 평가. Gate 3 중에는 실제 영상 게시를 계속 차단한다.

통과 기준: 정상/거절/부분 실패/timeout/중복/늦은 응답/편집 경합/전체 삭제 테스트 통과. 합성 한국어 절차 영상 10개(세로·가로·회전·작은 글씨·대기 화면 포함)를 별도로 평가한다. 후보 목표는 핵심 행동 설명 90% 이상 유효, 표시한 클릭 점 90% 이상 정답 영역 안, 개인정보 후보 재현율 95% 이상이다. null 클릭 비율·놓친 개인정보·수정 시간을 함께 기록하며 무표시로 성적을 높이지 않는다. 수치는 **검증 전 목표**이며 자동 게시 허용 기준이 아니다.

## 6. 순서 2 — Gate 4 저장되는 편집기

Gate 3에서 만든 최소 초안 저장 위에 실제 편집 API와 화면을 연결한다.

- `GET /api/guides/:id/draft`: revision·편집 문서·전체 scene graph·권한 범위의 프레임 경로. 현재 `serializeGuide()`의 요약 privacyCount만으로는 편집하지 않는다.
- `PATCH /api/guides/:id/draft`: baseRevision, mutationId, 검증된 편집 명령 목록. 제목/설명/순서/삭제/인접 병합/포인터/가림을 한 트랜잭션으로 반영한다.
- 같은 mutationId 재전송은 중복 적용하지 않는다. revision 불일치는 409와 최신 버전을 반환하고 무조건 덮어쓰는 마지막 저장 우선 방식을 쓰지 않는다.
- 입력은 짧게 지연해 자동 저장하되 요청을 순서대로 보낸다. 저장 중/저장됨/저장 실패/충돌을 구분한다. 저장 실패·충돌·미전송 변경이 있으면 게시를 차단한다.
- 병합은 인접 단계만 허용하고 대표 프레임을 하나 고르게 한다. 다른 프레임의 가림 좌표는 가져오지 않는다. 병합 후 문구·클릭·개인정보 확인을 다시 요구한다. 마지막 한 단계는 삭제할 수 없다.
- StepCanvas는 이미지 실제 표시 영역에 대해 좌표를 변환한다. 포인터 이동, 가림 추가/이동/크기 조절, 키보드 선택·이동·크기 조절, 실행 취소/다시 실행을 제공한다.
- 되돌리기도 서버에는 새 revision으로 저장한다. 새로고침 후 과거 undo 이력 복원은 이번 범위에 넣지 않는다.
- 한 단계 재생성은 해당 프레임과 최소 앞뒤 문맥만 전송한다. 생성 중 편집은 허용하되, 결과 적용은 baseRevision 검사 후 작성자가 선택한다.
- 개인정보 후보는 pending/masked/dismissed로 명시한다. 탐지 0건도 ‘개인정보 없음’이 아니라 ‘후보 0건, 직접 확인 필요’다. 제목·설명에 섞인 민감 정보도 검토 항목에 포함한다.

현재 `document.schemaVersion: 1`은 개인정보 확인을 `pending`으로만 허용한다. D1에서 수정 요청의 중복 기록(`guideId + mutationId`, 요청 지문, 기준/결과 revision)을 추가하고, E1에서 후보별 확인 상태·프레임/문구의 확인 지문을 포함하는 문서 v2로 확장한다. v1을 읽으면 확인은 모두 pending으로 옮기며 기존 기록을 확인 완료로 추정하지 않는다. 전체 삭제 후 같은 ID의 수정 요청으로 초안을 다시 만들지 않는다.

편집 명령은 제목/설명 변경, 재정렬, 단계 삭제, 인접 병합, 클릭 위치 변경/제거, 가림 추가/수정/제거의 허용 목록만 받는다. 브라우저가 raw object key·새 프레임 소속·revision·게시 상태를 직접 지정하지 못하게 한다. 저장 응답은 최신 문서와 서버 revision을 반환한다. 충돌 시 미전송 로컬 수정은 복사/복구할 수 있게 유지하고 자동 덮어쓰기나 자동 공개는 하지 않는다.

한 단계 재생성은 `POST /api/guides/:id/draft/steps/:stepId/analysis`에 runId·baseDraftRevision·현재 동의를 받아 기존 예산/큐 경로를 재사용하는 확장으로 설계한다. 결과 적용은 일반 편집 명령의 한 종류로 별도 요청하며, 제안의 guide/step/frame 지문·기준 revision을 다시 검사한다. 이 경로는 D3 전에는 제공하지 않는다.

통과 기준: 새로고침 복원, 두 탭 충돌, 응답 유실 재전송, 병합/재정렬 unique position, 세로/가로/줌 좌표, 화면 크기 변화, 토큰 없는 쓰기 거부, 삭제 중 저장 거부, 키보드 전용 사용을 검증한다. 게시 버튼은 아직 외부 공유를 만들지 않는다.

## 7. 순서 3 — Gate 5 개인정보 처리와 게시

### 7.1 가림 방식과 확인 규칙

공유용 이미지를 서버에서 새로 만든다. CSS 오버레이 뒤에 미가림 프레임을 제공하지 않는다. 대표 이미지·썸네일·공유 미리보기 모두 같은 게시본의 처리된 자산을 사용한다.

**원안 보완 제안:** 원안은 blur/pixelation이지만 ‘이미지에 구웠다’는 것만으로 민감한 글씨가 판독 불가능하다고 단정하지 않는다. 계좌·전화번호·비밀번호 등은 기본적으로 불투명 단색 덮기를 권장한다. 모자이크의 선택 제공 여부는 구현 전 결정한다. 이 문서는 기존 동작을 바꾸지 않는다.

- 각 단계의 화면과 제목·문구를 작성자가 확인해야 한다. 모든 개인정보 후보를 masked 또는 dismissed로 결정한 뒤에만 게시 요청을 받는다.
- 이미지/가림 변경은 해당 단계의 개인정보 확인을, 제목/문구 변경은 해당 텍스트 확인을 무효화한다. 새 AI 후보가 추가되어도 재확인한다.
- pixel 변환은 좌상단을 floor, 우하단을 ceil로 계산하고 이미지 경계로 제한해 가장자리 노출을 줄인다. 프레임과 출력 크기별로 같은 규칙을 테스트한다.
- 처리본은 재인코딩하고 불필요한 메타데이터를 제거한다. 검토한 단색 영역 안에 원본 픽셀이 남지 않는 합성 패턴 테스트를 둔다. 이것도 미탐지 영역의 안전까지 보장하지 않는다.

### 7.2 게시를 원자적으로 확정한다

`POST /api/guides/:id/publications`에 expectedDraftRevision·idempotencyKey를 보낸다. 서버가 확인 상태를 재검증하고 그 revision의 불변 snapshot을 만든다.

```text
요청/정리 대상 기록
  → 비공개 임시 게시 경로에 처리 이미지·썸네일 생성
  → 모든 자산 존재·처리 결과 검사
  → DB 트랜잭션으로 게시본 확정 + activePublicationId 교체
  → 새 공유 링크/갱신 완료 응답
```

- 모든 자산 준비 전에는 공개 조회가 새 게시본을 볼 수 없다. 실패·서버 종료 시 이전 게시본을 유지하고 임시 자산을 정리한다.
- 생성 중 초안이 바뀌면 revision 불일치로 확정을 거부하고 새 확인을 요청한다. 같은 게시 요청 재시도는 기존 작업을 조회하며 중복 게시하지 않는다.
- 전체 삭제 또는 게시 철회가 먼저 확정되면 늦은 게시 worker가 다시 공개할 수 없다. 삭제 세대/작업 소유권을 최종 트랜잭션에서 검사한다.
- 게시 후 편집은 비공개 초안에만 반영한다. 다시 게시해야 공개 결과가 바뀐다.
- `POST /api/guides/:id/unpublish`는 공개 참조를 먼저 철회하고 자산은 복구 가능한 삭제 대기 목록으로 정리한다. 예전 revision 자산 URL도 현재 공개 권한을 재확인한다.
- 기존 7일 ready/failed 정리 규칙을 그대로 게시 가이드 전체에 적용하면 안 된다. 초안·원본의 만료와 게시본의 보존을 분리하고 heartbeat나 조회가 보존 기간을 무한 연장하지 않게 한다.

게시 상태 조회는 `GET /api/guides/:id/publications/:publicationId`로 제공한다. 요청 ID가 같아도 원본 공유 옵션·기준 revision 등 요청 지문이 다르면 409다. 게시 job은 queued/running/succeeded/failed/cancelled와 독립된 lease를 가지며, 이미지 처리/자산 검증 뒤 최종 트랜잭션에서만 활성 게시 참조를 바꾼다. 공개 slug는 기존 내부 가이드 slug를 자동 공개하는 대신 게시 권한이 있는 별도 난수 참조로 연결한다.

보존 계약은 미공개 가이드의 현재 7일 정리, 비공개 원본/프레임 만료, 게시본 만료를 별도로 관리한다. 정확한 운영 기간은 E3 전에 확정한다. 게시 이미지가 여전히 유효하면 원본 만료만으로 공유 링크를 지우지 않는다. 반대로 원본/프레임이 만료된 제작 화면은 재분석·재편집을 차단하고 새 영상 업로드를 안내하며, 철회·전체 삭제는 허용한다. 원본이 없는데 원본 보기 옵션을 켜거나 공개 처리 이미지로 미가림 원본을 복원하지 않는다.

통과 기준: 무인증으로 원본/미가림 이미지/썸네일/임시 게시 이미지 접근 불가, 가림 밖 좌표 거부, 확인 뒤 변경 시 게시 거부, 중간 저장 실패 복구, 동시 게시/삭제/철회, 반복 요청, 만료 정리가 활성 게시본을 깨뜨리지 않음을 검증한다.

## 8. 순서 4 — Gate 6 공유 링크·모바일 뷰어

- `/g/:slug`는 활성 게시 snapshot만 표시한다. 편집 draft·AI 실행 결과를 직접 읽지 않는다.
- `GET /api/public/guides/:slug`와 공개 이미지 경로는 허용 목록 DTO를 사용한다. 제목·설명·단계·안전한 이미지 경로·뷰어용 포인터만 반환한다. 내부 object key·원본 위치·edit token·미가림 프레임 경로를 제외한다.
- 공개 이미지도 서버가 활성 게시본 소속을 확인한 뒤 스트리밍한다. 원본 버킷을 public으로 열지 않는다. 시범판은 이미지/메타데이터 `no-store`를 기본으로 해 철회 시 새 요청을 차단한다.
- 이미 다운로드·캡처되거나 외부 서비스에 남은 자료까지 회수할 수 있다고 약속하지 않는다. 메신저 미리보기 캐시가 즉시 지워진다고도 약속하지 않는다.
- 한 번에 한 단계, 큰 이전/다음 버튼, 현재 단계 표시, 쉬운 한국어를 사용한다. 가로 화면은 클릭 위치 중심 확대와 별도 확대 버튼을 제공한다. 스와이프/더블탭만으로 기능을 제공하지 않는다.
- 직접 조작은 키보드·터치로도 가능하게 하고, 시범 목표는 본문 18px 이상·주요 버튼 터치 영역 44px 이상으로 둔다. 화면 내 텍스트를 읽을 수 있는지 실제 기기에서 확인한다.
- Sites의 서버 렌더링 경로는 프로세서의 공개 API만 호출한다. 공유용 제목·설명·이미지는 확정된 게시본에서 생성하고 일반 방문과 미리보기 요청이 같은 버전을 보도록 한다.
- 원본 영상 보기 기본값은 꺼짐이다. 켤 때는 ‘가림이 적용되지 않은 원본이며 업로드 파일에는 음성도 있을 수 있음’을 별도 확인한다. 익명 링크 수신자에게도 원본 접근을 허용한다는 결과를 명시한다.
- 원본 제공은 활성 게시본의 opt-in을 확인하는 별도 스트리밍 경로와 Range 처리를 사용한다. 기본 공개 DTO에는 원본 경로가 없고 비활성화·철회·원본 만료 후에는 요청을 거부한다. 원본이 이미 지워졌으면 켜기 옵션을 제공하지 않는다.

통과 기준: 별도 기기·로그아웃 상태의 링크 접근, 카카오톡 내부 브라우저와 공유 미리보기, 세로/가로/확대/이전다음, 철회·만료, 원본 옵션의 기본 차단 및 명시적 허용 경계를 확인한다. CAPTCHA나 인증 절차를 자동 수행하는 기능은 만들지 않는다.

## 9. 순서 5 — Gate 7 실제 배포·사용자 검증

1. 외부 서비스를 만드는 대신 현재 배포 설계를 유지한다. 실제 사용자 시험 시점에만 필요한 비용·계정 설정을 확인한다.
2. 프로세서와 실제 PostgreSQL/App Storage를 먼저 준비한다. 마이그레이션·미디어 바이너리 검증·재시작·삭제 지연·늦은 쓰기·동시 worker를 실서비스 어댑터로 확인한다.
3. 이전 버전과 호환되는 추가 스키마부터 적용한다. 실제 AI 호출은 키·모델·동의 화면·예산 제한이 준비된 뒤 합성 데이터로 검증한다.
4. 프로세서 HTTPS 준비 후 Sites에 해당 주소를 연결한다. 이때까지 기존 공개 화면을 유지한다.
5. 수신자의 무로그인 접근 요구와 Sites의 배포 접근 수준을 일치시킨다. 공개 전환이 필요하면 그 시점에 명시적으로 승인받는다.
6. 전체 사용자 흐름과 장애 복구 확인 후 작은 시험군에 연다. 되돌릴 수 없는 DB 파괴 변경은 이 배포에 섞지 않는다.
7. 실제 설명 상황 10건을 시험한다. 녹화 종료→초안 준비 시간, 사람의 검토 시간, 공유까지 시간, 수정량, 추가 질문 없이 성공했는지를 분리해 기록한다.

원래 제품 가설의 기준은 **10건 중 7건 이상 추가 질문 없이 수행 성공**이다. ‘60초’는 아직 검증되지 않은 목표다. 서버 처리 시간과 사람의 검토 시간을 섞어 60초 달성을 주장하지 않는다. 실사용 시험에 실제 비밀번호·금융 인증값을 녹화하도록 요구하지 않는다.

## 10. 구현 전 확정할 항목과 바로 다음 작업

지금 결정을 받지 않아도 설계는 진행할 수 있지만, 관련 구현을 켜기 전에는 아래를 확정한다.

| 결정 | 제안 기본값 | 확정 시점 |
|---|---|---|
| 결과물 종류 | 녹화 영상 입력 → 단계별 링크. 자동 편집 동영상 출력은 별도 범위 | 이 설계 검토 시 |
| AI 모델·비용 한도 | 사용자 선택 Gemini로 시작. 가상 화면 시험만 로컬 UTC 하루 10회, 과금 등급은 사용자 확인 필요. 운영 일일/가이드 비용 예산은 미확정 | Gate 3B 운영 연결 전 |
| 민감정보 가림 방식 | 불투명 단색 덮기 우선, 모자이크 선택 제공은 보류 제안 | Gate 5 전 |
| 게시본 보존 기간 | 초안/원본의 7일 정리와 분리. 공개 링크의 만료 기간은 사용자 안내·저장 비용과 함께 결정 | Gate 5 전 |
| 원본 영상 옵션 | 원안대로 제공하되 기본 꺼짐·별도 경고·확인·철회 경로 필수 | Gate 6 전 |

**전체 계획 B1의 예산 계산 규칙을 로컬 구현·검증했고, 다음은 B2–B5의 저장·접수·큐·실환경 검증이다.** Gate 2 실기기 확인은 A0로 남긴다. 실제 AI 호출, 편집기 전체, 개인정보 처리, 공개 링크를 한 번에 구현하지 않는다. 기능별 완료 기록에는 구현한 것·테스트한 것·아직 미검증인 것을 함께 적는다. 웹 배포 이후 모바일 제작 보완(M1)까지의 순서는 [전체 개발 계획](DEVELOPMENT_PLAN.md)을 따른다.
