# B5 실행 조건 근거 연결 — 내부 구현

2026-09-18. **근거를 묶는 코드만 구현했다. 실제 근거 발급기와 서버 시작 연결은 없으며, 제품의 자동 AI 분석은 계속 꺼져 있다.** 개인 영상은 Replit 처리·저장 범위를 유지한다. 후속 승인에 따른 독립 합성 AI 시험 2회는 아래 최신 기록과 구분한다.

## 이번에 구현한 것

`artifacts/api-server/src/processor/analysis-readiness.ts`의 `EvidenceAnalysisReadiness`는 서버가 제공한 세 검증기의 결과를 받아 기존 접수/전송 검증 계약으로 연결한다. 기본 생성자는 검증기가 없으므로 요청을 거절한다. HTTP 본문, 환경 플래그, 예전 시험 결과를 가져와 준비 완료로 바꾸는 경로는 없다.

| 근거 | 함께 확인하는 범위 |
|---|---|
| 실행 환경 | 동일 배포, PostgreSQL 원장·내구 실행기·계수 원장, Replit 비공개 저장소, 프로젝트 전체 원자적 한도 차감, 호스팅 허용 범위, 프로젝트/키 버전 참조 |
| 승인 입력 | 가이드·전체 manifest 지문·장면 수·모델·프롬프트 버전, 합성 자료 승인, 모든 묶음의 전체 요청 상한 검토 참조 |
| 무료 프로젝트/정책 | 동일 배포·프로젝트·키 버전, 현재 모델, 무료 전용·유료 전환 금지, RPM/입력 TPM/RPD, 앱 예산 정책 |

이 값들의 **문자열 형식이 맞는다는 사실은 실제 검증 증거가 아니다**. 각 검증기는 현재 사실을 확인하고 전체 근거 레코드에 대한 동기식 `isCurrent`를 제공해야 한다. HTTP/환경 JSON을 그대로 돌려주거나 항상 `true`를 반환하는 구현은 허용하지 않는다. 검증기 계약 자체는 네트워크 방화벽이 아니다.

- 세 근거가 전부 유효해야 한다. 서로 다른 배포·프로젝트·키 버전·입력의 근거를 섞지 않는다.
- 근거는 최대 30초이며 새 스냅샷은 가장 이른 확인 시각/만료 시각을 사용한다. 조회할 때 유효기간을 새로 늘리지 않는다.
- 만료, UTC 앱 날짜/태평양 공급자 날짜 변경, 시간 역행, 철회, 실패 시 거절한다. `isCurrent`의 Promise/문자열/숫자는 참으로 취급하지 않는다.
- 조회는 기본 5초 이내에 실패하며, 취소를 무시한 늦은 결과는 근거로 등록하지 않는다. 진행 중 조회는 최대 8개, 근거 보관은 최대 64개다. 멈춘 검증기는 실제 완료 전까지 슬롯을 점유한다.
- `clear()`는 발급한 근거와 진행 중 조회를 함께 무효화한다. 입력/키/정책/환경 변경 시 실제 근거 발급기도 변경을 감지해 기존 레코드를 철회해야 한다.
- 반환값과 검증기 입력을 복제하며 원문 오류·경로·키 값은 노출하지 않는다. 키 버전 참조는 비밀 키 자체가 아니다.
- 기존 예산 검증과 저장 직전 검증을 재사용한다. 조회가 성공해도 저장 전에 철회되면 분석 예약은 남지 않는다.

## 그대로 유지한 경계

사용자 동의/소유권은 기존 분석 API와 내구 상태 검증의 책임이다. 이 연결부가 동의를 만들거나 생략하지 않는다. 준비 스냅샷도 단독 전송 허가가 아니다. 기존 실제 이미지 해시/디코딩 검증, 정확한 요청 지문의 검토 상한, 별도 원장을 거치는 계수, 최신 실측 검증, 최종 잠금/전송 검사 모두 필요하다.

`inputTokenBound`는 승인 자료의 **모든 묶음에 대한 검토된 상한**을 참조하는 필드다. 이 연결부는 토큰 수를 계산하지 않으며 이미지 개수·바이트 수·과거 성공 요청으로 상한을 추정하지 않는다. 정확한 요청의 상한 검증기와 일치하는 근거를 실제 발급기가 제공해야 한다.

현재 `server.ts`/시작 코드에는 이 연결부나 실제 근거 발급기를 넣지 않았다. 기본 새 분석은 기존처럼 503이며, `countTokens`·`generateContent`·AI dispatcher를 실행하지 않는다. 스키마·의존성·클라이언트 UI도 변경하지 않았다.

### 2026-09-18 최신 — Replit에서 합성 AI 독립 시험 성공, 제품 자동 연결은 그대로 꺼짐

영상/추출 화면의 외부 AI 전송을 설명한 뒤 사용자가 개발에 필요한 시험 진행을 요청했다. 개인정보 없는 내장 화면만 사용하는 **계수 1회 + 생성 1회**로 실행 범위를 알리고, 기존 Replit 프로젝트/clean/커밋 확인 → 무전송 준비 검사 → 두 실호출 → 저장 결과 검토를 마쳤다. 개인 녹화물·서버 영상·초안은 열거나 전송하지 않았다.

이것은 기존 개발용 진단의 Replit 실환경 시험이다. **제품 readiness/시작 코드/거절 조건은 변경하지 않았다.** 일반 사용자용 외부 AI 전송, 운영 검증 완성, 개인정보 탐지/가림, 앱의 자동 초안 반영이 완료된 것은 아니다. 입력 상한은 여전히 미확정이며 이번 측정값을 범용 상한이나 30초 자동 근거로 바꾸지 않는다. 자동 분석 활성화·배포·권한/결제 변경·새 키·서버 재시작·DB/Storage 변경은 없고 진단 예약/결과만 Git 제외 경로에 남았다. Replit 작업본 clean을 확인하고 로컬 MD만 갱신했다.

### 앞선 2026-09-18 — 남은 구현 의존성 대조, 운영 점검/요청 보호 분리 제안

계정 화면 확인 뒤 실제 소스와 설치 SDK를 대조했다. 같은 UI·영상·DB 시험을 다시 실행하지 않았다. **남은 부분은 확인값을 채우면 끝나는 연결 작업이 아니다.** 현재 계약을 만족하는 실제 근거 공급원이 없으므로, 조회 권한/공급자 지원을 확보하거나 검증 계약을 명시적으로 재설계해야 한다. 사용자 결정 전까지 기존 거절 조건을 유지한다.

| 소스에서 확인한 의존성 | 현재 결론 |
|---|---|

**검토 제안(미승인·미구현):** 운영자가 확인해야 하는 플랫폼 정책/요금 조건과 앱이 요청마다 직접 집행할 수 있는 보호를 나눈다. 운영 점검에는 대상 프로젝트·확인 범위·시점·변경 시 재검토 책임을 명시하되, 이를 `verified`라는 자동 증명으로 포장하지 않는다. 실행 보호에는 소유권·승인 합성 입력의 정확한 지문·승인/철회·명시적 목적지·DB 기반 요청 한도·중복 방지·실패 시 거절을 유지한다. 정확한 입력 상한과 계수 단계의 허가 방식은 별도로 설계/검증해야 한다.

이 제안은 **플랫폼 사실을 직전 30초마다 자동으로 증명한다는 현재 요구를 운영 점검으로 대체하는 설계 변경**을 포함한다. 따라서 점검 뒤의 계정/플랫폼 변경을 즉시 자동 감지한다는 보장은 사라진다. 단순 리팩터링이나 기존 조건을 이미 충족한 구현으로 처리하지 않으며, 사용자에게 이 차이를 설명하고 승인받기 전에는 제품 코드/검사 기대값을 바꾸지 않는다. 기존의 확인되지 않은 버킷 권한은 계속 미확인으로 남긴다.

개인 영상의 허용 범위는 여전히 Replit 처리·저장뿐이다. Google의 현재 무료 서비스 약관은 제출 자료의 제품 개선 이용과 사람 검토 가능성을 안내하며 민감·기밀·개인정보 제출을 금한다. 따라서 무료 상태 확인을 개인 화면 전송 승인으로 취급하지 않는다. [Google 무료 서비스 데이터 조건](https://ai.google.dev/gemini-api/terms#unpaid-services) 설계 검토를 승인하더라도 AI 실호출·개인 영상 전송·유료 전환·배포·권한 변경은 별도 승인 사항이다.

이번에는 로컬 소스/문서와 공개 공식 자료만 읽고 MD에 의존성과 제안을 기록했다. 계정/브라우저 재조회, 사용자 영상 열람, 외부 AI/DB/Storage 호출, 제품 코드·설정 변경, 테스트 재실행, 커밋/푸시는 하지 않았다.
