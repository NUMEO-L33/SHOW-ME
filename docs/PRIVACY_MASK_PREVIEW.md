# 수동 가림 영역·비공개 처리본 — 2026-09-20

기존 개발 계획의 목표/정책은 바꾸지 않았다. D2의 가림 편집과 E2의 픽셀 처리 기반을 먼저 연결한 로컬 구현이다. **E1 개인정보 확인 계약, E2 게시 자산 저장, E3 게시 확정 완료는 아니다.** 공개 공유와 일반 개인 영상 AI 전송을 활성화하지 않았다.

## 구현한 것

- 실제 편집기에 가림 영역 추가/삭제/켜기/끄기, 위치·크기 숫자 입력, 화면 눌러 이동, 방향키 이동과 Shift+방향키 크기 조절을 추가했다. 최대 20개이며 원본 프레임에 묶인 기존 초안 요소로 자동 저장한다. 기존 revision 충돌·응답 유실 재전송 보호를 재사용한다.
- 편집용 영역 표시는 원본 위의 표시라고 명시한다. 이것을 가림 완료 이미지로 표시하지 않는다. `저장된 가림 이미지 확인`을 눌러 서버가 실제로 변환한 전체 이미지와 썸네일을 별도로 확인한다.
- 저장되지 않은 변경, 저장 중, 저장 실패/충돌은 미리보기를 막는다. 편집·revision 변경/닫기/언마운트는 진행 요청을 취소하고 이전 처리본을 숨기며 blob URL을 해제한다. 늦은 응답은 다시 나타나지 않는다. 이미지 표시 오류에도 원본을 대신 표시하지 않는다.
- 가림이 0개 또는 모두 꺼져 있으면 원본 내용이 남는다고 안내한다. 자동 탐지나 안전 판정으로 표현하지 않으며 제목·설명도 직접 확인하도록 안내한다.

## 서버 경계

`GET /api/guides/:guideId/privacy-preview/:stepId/:variant` (`frame` 또는 `thumbnail`)

- 소유자 Bearer 인증, `X-ShowMe-Draft-Revision`, `X-ShowMe-Input-Fingerprint`가 필요하다. 쿼리 문자열/이미지 티켓만으로 접근할 수 없다. 프레임 object key나 가림 좌표를 요청에서 받지 않고 저장된 초안·소유 가이드에서 결정한다.
- ready 가이드, 현재 미디어 지문, 저장 revision, 실제 편집 단계, 대표 프레임 소속과 정규 키를 확인한다. 처리 후 같은 검사를 다시 수행해 변경·삭제된 작업의 결과를 반환하지 않는다. 공개 경로가 아니며 `no-store`다.
- `enabled`가 가림 여부를 결정한다. enabled=true이면 visible=false나 zIndex와 무관하게 픽셀을 대체한다. 꺼진 가림은 의도적으로 처리하지 않으며 이를 개인정보 확인 완료로 바꾸지 않는다.
- 앱 인스턴스의 미리보기 작업은 동시에 1개, 요청은 IP별 분당 20회다. 저장소 읽기를 포함해 25초, 디코딩은 최대 15초다. 저장소가 취소를 무시해 늦게 반환하면 스트림을 닫고 해당 작업이 정리될 때까지 점유를 유지한다. 고장난 저장소에서 새 작업을 끝없이 쌓지 않는다.
- 입력은 최대 2 MiB의 기존 단일 baseline JPEG, 가로/세로 각각 최대 4096 및 총 4,194,304픽셀로 제한한다. 기존 엄격한 JPEG 검사와 FFmpeg pipe-only 디코딩을 사용한다. 외부 주소나 파일 경로는 클라이언트가 제공하지 못한다. 오류에 키·원문·개인정보를 넣지 않는다.
- 영상·원본 이미지·초안은 바꾸지 않는다. 서버/브라우저 메모리의 처리본만 만들며, 처리본을 Storage에 저장하거나 공유 링크를 발급하지 않는다. DB schema/migration 변경도 없다.

## 실제 픽셀 변환

- 좌상단 floor / 우하단 ceil, 원본 기준 8픽셀 여백, 이미지 경계 제한을 적용한다. 잘못된 percent 영역은 보정해 수용하지 않고 서버에서 거절한다.
- 원본 값을 평균/축소해 모자이크를 만드는 대신 고정 보라색 팔레트의 불투명 타일로 RGB를 덮는다. 타일은 위치에만 의존하며 원본 내용·영역 순서·겹침에 의존하지 않는다.
- 결과를 손실 없는 RGB PNG로 새로 인코딩한다. IHDR/IDAT/IEND만 쓰므로 원본 JPEG의 메타데이터나 숨은 원문을 복사하지 않는다. 썸네일은 이미 대체된 RGB에서만 생성한다.
- 이는 **선택 영역의 처리 방식** 검증이다. 선택하지 않은 개인정보, 영역 밖에 이미 포함된 내용, 사람이 놓친 부분, 설명에 남은 개인정보의 안전을 보장하지 않는다. 현재 개인 영상은 Replit 처리·저장만 허용하는 기존 정책과 AI 원본 전송 안내를 유지한다.

## 검증

- 새 검사: 서버 13개(픽셀/PNG 5 + 비공개 API 8), 클라이언트 5개. 서로 다른 원본 RGB/합성 JPEG의 선택 영역을 대체하면 결과가 같은지, 썸네일 일치, 원본 불변, PNG를 실제 FFmpeg로 다시 읽었을 때 픽셀 일치와 메타데이터 제외를 검사했다.
- 무권한/잘못된 인증, 잘못된 좌표·revision·지문·종류, 삭제된 단계, 다른 프레임, 저장 충돌/삭제 경합, 숨겨진 enabled 가림, disabled 영역, 저장소 오류·초과 크기·지연/늦은 스트림·동시 작업 제한을 검사했다.
- 최종 전체 **872개 통과**(이관 99 / 서버 682 / 클라이언트 91), 실패·취소·생략 0, 종료 코드 0. 초기 전체 869개 통과 후 서버 경계 검사 3개를 추가한 최종 실행이다. 별도 API 8개 및 제품/테스트 타입 검사도 통과했다.
- 서버/화면 타입 검사 및 양쪽 빌드 통과. 기존 화면 소스맵 경고와 568.20 kB 번들 경고는 남는다. pnpm의 자동 재설치 제안은 수행하지 않고 기존 컴파일러·기존 Windows 보조 라이브러리로 빌드했다. 의존성/lockfile을 바꾸지 않았다.
- 컴퓨터 사용 스킬의 브라우저 경로로 별도 로컬 합성 서버를 확인했다. 기존 합성 MP4를 실제 업로드 API·FFmpeg·JSON 저장소로 처리한 뒤 시험 전용 진입 페이지로 해당 편집기만 열었다. 브라우저 파일 선택 자동화는 권한 부족으로 실패하여 브라우저 업로드 UI 검증으로 세지 않는다. 확장 권한을 바꾸지 않았다.
- 가림 추가→숫자/키보드 조정→자동 저장→실제 처리본/썸네일, 새로고침 후 좌표 복원, 편집 직후 이전 처리본 숨김을 확인했다. 390px/320px 화면에서 문서/대화상자의 가로 넘침이 없었고 320px에서 결과와 조작부를 시각 확인했다.
- 503을 주입하자 처리본이 사라지고 원본 대체 없이 오류가 표시됐다. 다른 편집자의 revision을 먼저 저장한 후 좌표를 수정하면 저장 충돌이 표시되고 입력 27은 유지되지만 미리보기는 비활성화됐다. 서버의 값 26은 덮어쓰이지 않았다.
- 이 로컬 UI 시험은 AI 시작 0, 미리보기 요청 5(정상 두 쌍과 의도적 실패 1), 저장 요청 5(충돌 포함)였다. 시험 서버는 외부 fetch를 거부하고 CSP를 같은 출처로 제한했다. 전체 서비스의 네트워크 감사라는 뜻은 아니다.
- 임시 서버 종료와 해당 실행의 합성 저장 폴더 삭제를 확인했다. 원래 합성 MP4는 보존했다. 브라우저 크기 설정을 복원하고 시험 탭을 닫았다. 개인 브라우저 자료/영상, Replit DB/Storage, Google 키/호출에는 접근하지 않았다.

로컬 UI 보조 도구는 상위 작업 폴더의 `outputs/replit-ui-runtime/privacy-preview-server.mjs`와 `run-privacy-preview.mjs`에 있으며 제품 시작 경로에 포함하지 않는다.

## 남은 순서

1. E1: 후보별 pending/masked/dismissed, 화면·문구 확인 지문과 변경 시 재확인 계약. 현재 문서 v1의 `privacyReview: pending`을 유지한다.
2. E2/E3: 처리 자산의 내구 저장, 모든 자산 완료 후 불변 게시본 확정, 충돌/삭제/늦은 쓰기 정리, 철회·15일 만료.
3. 공개 API/뷰어는 처리된 활성 게시본만 읽도록 연결하고 실제 환경·전체 흐름을 검증한다. 원본 보기 opt-in은 별도다.

가림 편집의 실행 취소/다시 실행·드래그 핸들, AI 후보별 선택 검토 등 D2/E1의 남은 항목까지 완료한 것으로 표시하지 않는다. 이 기능의 Replit 코드 반영/재시작/실환경 검증도 로컬 결과와 구분한다.
