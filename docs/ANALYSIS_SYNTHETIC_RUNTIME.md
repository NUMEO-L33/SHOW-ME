# B5 후속: 고정 합성 자료 승인과 실행 환경 연결

2026-09-19. [계수·생성 허가 분리](ANALYSIS_BOUNDED_COUNT.md)의 다음 단계다. 원본 요구 MD는 수정하지 않았다. 내부 연결 코드를 구현하고 실제 임시 DB로 검증했으며, 제품 시작 코드·HTTP에는 아직 등록하지 않았다.

## 구현한 연결

`createFixedSyntheticAnalysisRuntime`은 신뢰할 수 있는 서버 내부 호출자가 제공한 기존 PostgreSQL pool, 배포/프로젝트/키 버전 참조, 명시적 Replit 버킷·접두사, 합성 입력 승인을 받는다.

- 저장소·DB 점검기·운영 기록 조회·접수·계수·공통 한도·실행기를 한 구성 안에서 만든다. 모든 DB 구성 요소는 같은 pool을 사용한다. 실제 API에 연결할 때는 반환된 repository/storage를 함께 사용해야 한다.
- 실행 환경 근거는 실제 `PostgresAnalysisDatabaseProbe`를 매 조회마다 호출한다. DB 스키마/이력/권한/공통 중지 상태의 기존 읽기 전용 검사를 재사용하며 결과를 과거 기록으로 대체하지 않는다.
- 운영 기록은 같은 pool의 `PostgresAnalysisOperationsStore`를 읽는다. 기록의 배포·프로젝트·키 버전·저장소 참조가 구성과 일치해야 한다. 저장소 참조는 정확한 버킷 ID와 접두사의 해시다.
- 계수와 생성은 같은 readiness와 repository를 사용한다. 계수 우회용 상한 검증기나 항상 참인 `isCurrent`는 넣지 않는다. 생성 어댑터는 외부에 노출하지 않고 기존 잠금 실행기 내부에서만 사용한다.
- 기본값은 비활성이다. 생성만으로 DB/Storage/AI를 호출하거나 worker를 시작하지 않는다. 내부의 명시적 실행 승인과 키, 유효한 운영·입력 근거가 별도로 필요하다.
- `stop()`은 합성 승인과 모든 로컬 근거/측정값을 무효화하고 실행기를 중단한다. 호출자가 소유한 pool을 닫거나 DB 중지를 해제하지 않는다. 같은 인스턴스의 재시작 기능은 없다.

## 합성 입력 승인 범위

`FixedSyntheticInputSource`는 저장소에 이미 포함된 **고정 합성 화면 두 장**만 대상으로 한다. 이전 브라우저 검사의 3장짜리 영상, 임의의 ‘synthetic’ 이름 파일, 사용자가 만든 화면은 이 승인과 같지 않다.

승인은 서버 내부에서 명시한 guide ID, 전체 manifest 지문, 장면 수, 모델/프롬프트 버전, 배포 참조, 승인 ID, 유효기간, 계수 제한에 묶인다. 최대 유효기간은 24시간이며 HTTP·환경 JSON·브라우저 복구 기록에서 자동 발급하지 않는다. 범용 관리자 승인 UI나 영속 승인 저장소를 만들었다는 뜻은 아니다.

근거 조회 시 지정한 가이드 하나의 현재 manifest·장면 수·크기·시각을 대조한다. 허용 이미지의 해시는 caller에게 받지 않고 고정 합성 자료에서 계산한다. 이 조회 단계에서는 이미지 전체를 다시 다운로드/디코딩하지 않는다.

실제 이미지가 필요한 단계에서는 같은 source의 기존 private loader가 저장소 경로·가이드 상태·현재 manifest·각 이미지 SHA-256·JPEG 구조·로컬 디코딩을 확인한다. 읽는 이미지가 허용된 바이트와 하나라도 다르면 계수/생성으로 보내지 않는다. 제목·설명·파일명으로 합성 여부를 판정하지 않으며, 영상 원본을 읽거나 외부로 보내지 않는다.

승인을 철회하거나 해당 인스턴스를 중단하면 다시 사용할 수 없다. 프로세스 재시작 뒤 임의 업로드를 기존 승인으로 복원하지 않는다. 다른 프로세스까지 중단해야 할 때는 기존 운영 기록 철회와 DB의 공통 중지 잠금을 사용해야 한다.

## 근거의 수명과 한계

새 로컬 근거는 실제 조회를 거쳐 발급하고 최대 30초 동안만 유지한다. 원본 승인 만료보다 길게 연장하지 않으며 반환값 전체를 비교한다. 조회 실패·취소·시간 역행·날짜 경계·만료 시 거절한다. 조회 대기는 최대 4초이고 같은 소스의 취소를 무시한 작업은 실제 완료 전까지 실행 슬롯을 점유한다. 기록은 최대 64개다.

동기식 `isCurrent`는 로컬 수명/철회 검사이지 원격 DB·계정·IAM 변경을 즉시 감지하는 수단이 아니다. 실제 전송 직전의 DB 잠금·동의·manifest·공통 중지 검사는 그대로 필요하다.

Replit 저장소 adapter를 구성하고 대상 참조를 비교하는 것은 원격 IAM이나 무료 정책의 자동 증명이 아니다. 프로젝트와 키 버전 참조는 신뢰할 수 있는 서버 구성 및 운영자의 현재 확인 기록에 의존한다. 이 코드가 Google 계정에 접속하여 키의 프로젝트 소속을 확인하지는 않는다. 실행 환경 근거는 구성과 실제 DB 관측을 연결하는 범위이며 기존 수동 운영 점검 책임을 없애지 않는다.

## 검증 결과

- 새 단위 검사 **6개**: 전체 근거 비교/만료, 취소·늦은 결과·실행 슬롯 유지, 실패 시 무효화/오류 비공개, 실제 고정 JPEG 읽기/변조 거절/철회, 승인 범위 제한, 기본 비활성/생성 무호출/호출자 pool 보존.
- 일반 전체 **820개(이관 91 + 서버 643 + 클라이언트 86)** 통과. 실패·취소·생략 0, 종료 코드 0.
- 실제 PostgreSQL **86개** 통과. 새 두 통합 검사는 실제 DB 점검·운영 기록·접수·기존 JPEG 해시/디코더·계수·생성·결과 저장을 연결한다. 외부 Storage/AI transport만 테스트 대역을 사용했다. 정상 흐름은 계수 1회 → 생성 1회이며, 키 버전 참조 불일치·승인 철회·변조 이미지에서 AI 전송은 0회다.
- API 제품/테스트 TypeScript 검사 및 서버 빌드 통과.
- 일회용 loopback Docker DB/컨테이너 자동 정리를 확인했다. 기존 앱 DB나 다른 컨테이너는 정리 대상이 아니다.

실제 AI/외부 Storage 호출, 개인 영상 접근·전송, Replit DB 변경, 배포, 커밋/푸시는 없었다. 테스트용 운영 기록은 허구이며 실제 사용자 계정의 운영 승인을 대신하지 않는다.

## 다음 단계
