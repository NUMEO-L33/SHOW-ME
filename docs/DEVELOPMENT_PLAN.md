# ShowMe 전체 개발 계획 v1

작성일: 2026-09-14 · 출발 코드: `317f9bf` · 상태: 전체 설계 정리, B1 로컬 구현·검증 완료

## 1. 이 문서부터 읽기

이 문서는 **무엇을, 어떤 순서로, 어디까지 검증하고 완성할지**의 기준이다. 세부 계약은 [기능별 상세 설계](NEXT_PHASE_DESIGN.md), [AI 실행·예산 설계](ANALYSIS_EXECUTION_DESIGN.md), 이미 구현된 HTTP 계약은 [분석 API](ANALYSIS_API.md)에 둔다. [진행 기록](IMPLEMENTATION_PHASES.md)은 실제 완료 결과를 기록한다. 계획의 체크 항목은 테스트 증거가 있어야 완료로 바꾼다.

충돌 시 구현 여부는 코드·검증 기록, 앞으로의 제품 범위와 순서는 이 문서를 기준으로 한다. 예전 체크포인트의 테스트 수와 날짜는 당시 기록이며 최신 상태로 읽지 않는다. 사용자 선택이 바뀌면 이 문서의 결정 기록과 영향을 받는 계약을 함께 수정한다.

## 2. 마지막에 완성할 제품

화면 녹화 한 번으로, 상대방이 혼자 따라 할 수 있는 **한국어 단계별 안내 링크**를 만든다. 제작자는 설명·클릭 후보·가림을 검토하고 공유하며, 수신자는 카카오톡 등에서 링크를 열어 앱 설치·로그인 없이 본다.

```text
녹화 / 영상 파일 → 업로드·화면 추출 → 전송 동의·AI 초안
  → 설명·순서·클릭·가림 검토/저장 → 공유용 이미지 생성·게시
  → 링크 전달 → 휴대전화/PC에서 단계별 보기
```

- 입력: 직접 녹화 또는 MP4/MOV/WebM. 기존 직접 녹화 4분/64 MiB, 파일 업로드 500 MiB 제한 유지. 직접 녹화 오디오 미수집.
- 결과: 단계별 안내 링크. 자동 편집한 완성 동영상 출력·음성 내레이션은 이번 완성 범위가 아니다. 원본 영상 보기는 별도 선택이며 기본 꺼짐이다.
- 제작 경험: AI 결과를 곧바로 공개하지 않는다. 수정할 수 있고, 저장 결과·개인정보 확인이 끝나야 게시한다.
- 수신 경험: 한 단계씩 큰 화면, 쉬운 한국어, 이전/다음·확대. 가로 녹화도 휴대전화에서 확인할 수 있어야 한다.
- 웹 1차 완성 후 간단한 모바일 **제작 화면**을 보완한다. 모바일 뷰어는 웹 1차 완성에 포함한다. 별도 네이티브 앱·앱스토어 출시는 범위 밖이다.
- 제외: 계정/팀/결제/관리 대시보드, 자동 인증·CAPTCHA 수행, AI 편집 명령, 무제한 무료 사용, 학습 제외·정확도·60초 완성 보장.

## 3. 현재 출발점

| 영역 | 코드·로컬 검증 | 실제 사용/운영 |
|---|---|---|
| 녹화·업로드·화면 추출 | 구현, 실제 FFmpeg fixture 검증 | 브라우저 공유 권한·실제 기기 전체 흐름 확인 남음 |
| Gemini | 가상 화면 2장 실제 3.5 Flash-Lite 분석 성공 | 사용자 녹화 자동 분석 꺼짐 |
| 분석 요청·조회·취소 | 인증·동의 형식·중복·취소 API 구현 | 운영 접수기 없음, 새 요청 503 |
| AI 작업 큐·운영 예산 | 전체 계약 설계, B1 계산 규칙 구현 | DB 예약·작업 큐·운영 연결 미구현 |
| 편집 | 별도 초안·revision 저장 기반 | 편집 API·화면 연결 미구현 |
| 개인정보 가림·공개 링크 | 기존 데모와 설계만 존재 | 실제 영상의 공개 계속 차단 |
| 운영 배포 | 어댑터·배포 설정 존재 | 실제 PostgreSQL/저장소 경합·배포 검증 남음 |

출발 커밋의 검증은 processor 171개 + client 4개, 총 175개였다. 이번 B1까지는 processor 181개 + client 4개, **총 185개 및 타입·린트·빌드 통과**다. 실제 운영 완료를 뜻하지 않는다. 공개 Site는 이전 프로토타입이다.

## 4. 유지할 구조와 책임

| 구성 | 책임 | 금지할 경계 침범 |
|---|---|---|
| 기존 Sites 화면 | 녹화·업로드·검토·편집·공개 뷰어 | Google 키, 직접 DB 접속, 원본 공개 URL 생성 |
| 독립 Node 프로세서 | 인증된 API, 미디어/AI/게시 작업, 자산 접근 제어 | HTTP 요청 안에서 긴 AI/게시 작업 완료까지 기다리기 |
| PostgreSQL | 가이드·초안·실행·예산·게시 상태의 기준 데이터 | 운영 데이터를 브라우저/인메모리 상태만으로 보관 |
| 비공개 App Storage | 원본·프레임·가림을 적용한 게시 이미지 | 버킷 전체 공개, 내부 object key 직접 반환 |
| 로컬 JSON/파일 | 개발·단일 프로세스 계약 시험 | 분산 운영 예산이 검증됐다고 간주 |

미디어·AI·게시 작업의 실행 슬롯과 소유권을 분리한다. 새 프레임워크·외부 큐 서비스·D1/R2·로그인을 추가하지 않는다. 당장은 DB의 대기 실행 행 자체를 내구성 있는 AI 큐로 사용한다.

## 5. 실행 순서와 체크리스트

`완료`는 해당 묶음의 로컬 완료이고 운영 개방은 R1/R2에서 별도 판단한다. 한 작업 묶음을 끝낼 때마다 구현 내용·테스트·미검증 항목을 짧게 보고한다.

| 순서/ID | 작업 묶음 | 결과물과 통과 기준 | 선행 조건 | 상태 |
|---|---|---|---|---|
| A0 | 기존 녹화·업로드 실기기 확인 | 공유 취소/종료, 무음, 세로·가로·회전, 재접속·전체 삭제 기록 | 현재 코드 | 미검증, R1 전 필수 |
| B0 | 전체 설계 정리 | 범위·계약·순서·결정 지점·출시 기준 문서 | 현재 코드 확인 | 완료 |
| B1 | 예산 계산 규칙 | 요청/토큰/금액 상한, 올림·정수 오버플로·불확실 사용량 규칙 테스트 | B0 | 로컬 완료 |
| B2 | 예산·묶음 저장 계약 | 추가 migration, 중복 예약 방지, 실행+예약 원자 저장, 삭제 후 소비 기록 보존 | B1 | 다음 작업 |
| B3 | 내구성 있는 접수기 | 같은 ID 중복 접수·응답 유실 복구, 전체/가이드 한도, 준비 전 거절 | B2 | 대기 |
| B4 | AI dispatcher·복구 | 별도 슬롯, lease/시도 제한, 재시작, 취소/삭제, 성공 묶음 재사용 | B3 | 대기 |
| B5 | 실제 DB 검증·제한된 AI 연결 | 다중 DB 연결 경합·정산, 합성 입력만 제한 실호출, 자동 활성화 없음 | B4 + 사용 설정 확인 | 대기 |
| C1 | AI 동의·진행·결과 화면 | 동의 전 전송 없음, 준비/분석/실패/취소/검토 필요 구분, 새로고침 복구 | B4, 실행은 B5 후 | 대기 |
| C2 | 한국어·좌표·개인정보 품질 | 합성 절차 10개 평가, 누락·null 클릭·수정량 기록 | C1 | 대기 |
| D1 | 편집 API | 초안 조회·명령 저장·같은 수정 ID 재전송·409 충돌·서버 정본 복구 | C1 | 대기 |
| D2 | 편집 화면·StepCanvas | 문구/순서/삭제/인접 병합, 클릭·가림 조작, 저장 표시·키보드·터치 | D1 | 대기 |
| D3 | 한 단계 재생성 | 해당 화면+문맥만 분석, 같은 예산 경로 사용, 사람이 결과 적용, 충돌 보호 | D2 + B5 | 대기 |
| E1 | 개인정보 확인 계약 | 글·화면 확인, 후보별 처리, 변경 시 재확인, 저장 실패 시 게시 금지 | D2 + 가림 방식 결정 | 대기 |
| E2 | 게시 이미지 생성 | 가림을 픽셀에 반영, 썸네일 포함, 원본/임시 이미지 비노출 테스트 | E1 | 대기 |
| E3 | 게시·철회·보존 | 불변 게시본, 원자적 참조 교체, 경합/늦은 쓰기/삭제/만료, 이전 게시본 보존 | E2 + 보존 기간 결정 | 대기 |
| F1 | 공개 API·모바일 뷰어 | 무로그인 링크·확대·이전/다음·철회, 공개 허용 필드만 반환 | E3 | 대기 |
| F2 | 공유 미리보기·원본 옵션 | 같은 게시본 metadata, 원본 기본 차단·명시 동의·Range·철회/만료 | F1 + 원본 정책 결정 | 대기 |
| R1 | 운영 환경 검증 | 실제 DB/Storage·migration·재시작·보안 점검·A0·전체 흐름·복구 기록 | B5, C2, D3, F2 | 대기 |
| R2 | 제한된 공개 시험 | 배포/공개 승인, 모니터링·한도·되돌리기, 실제 설명 10건 평가 | R1 | 대기 |
| M1 | 모바일 제작 간소화 | OS 녹화 파일 업로드, 세로 검토·문구 수정·가림 확인·공유 실기기 확인 | 웹 R2 안정화 | 후속 |

B1→B2처럼 순서대로 개발하되 A0의 사용자 브라우저 확인이 필요한 경우 미검증으로 남기고 서버 개발을 진행할 수 있다. 하지만 A0가 안 끝났는데 R1/R2를 완료 처리하지 않는다. B1–B4 중 모의 공급자로 성공한 테스트는 Google 실제 연결 검증으로 세지 않는다.

## 6. 화면과 실패 상태 설계

| 화면 | 사용자 행동 | 반드시 구분할 상태 |
|---|---|---|
| 시작/입력 | 직접 녹화 또는 파일 선택 | 미지원·권한 취소·용량 초과·네트워크 실패·복구 키 저장 실패 |
| 추출 결과/AI 동의 | 화면 확인, 외부 전송 설명 확인 후 분석 | 프레임 준비 완료와 AI 완료 구분, 서버 미준비·비용 한도·동의 미완료 |
| 분석 진행 | 진행 확인·취소 | 접수 확인 지연·대기·실행·부분 실패·완료·취소, 임의 퍼센트/완료 문구 금지 |
| 검토/편집 | 문구·단계·클릭·가림 수정 | 저장 전·저장 중·저장 완료·실패·충돌, 후보 0건도 직접 확인 |
| 게시 확인 | 개인정보·원본 공유 범위 확인 | 미확인/미저장 차단, 생성 중, 실패 시 이전 게시본 유지, 공개 확정 후 링크 |
| 공유 뷰어 | 단계 이동·확대 | 로딩·없는/철회/만료 링크, 이미지 실패, 원본 옵션 비허용 |

새 마케팅 화면이나 디자인 전면 개편은 하지 않는다. 기존 브랜드를 유지하고 쉬운 한국어·큰 주요 조작·화면 비율에 맞춘 좌표로 확장한다. 키보드만으로 핵심 작업을 수행할 수 있어야 하고, 색·드래그·스와이프만으로 기능을 제공하지 않는다.

## 7. 미확정 항목을 처리하는 방법

미확정이라고 전체 개발을 멈추지는 않는다. 아래 안전 기본값으로 코드·모의 시험은 진행하되, 사용자 선택이나 외부 조건 확인이 필요한 실제 활성화는 하지 않는다.

| 결정 | 개발 중 기준 | 확정/승인이 필요한 시점 |
|---|---|---|
| AI 운영 일일/가이드 한도·단가 | 값 없으면 실행 거절. 테스트는 가상 숫자. 무료 시험 파일 한도와 분리 | B5 실제 운영 접수 연결 전 |
| 실제 사용자 화면의 외부 전송 조건 | 합성 화면만. 기존 확인값을 실제 영상 동의로 재사용하지 않음 | B5/C1 실제 영상 전송 전 |
| AI 운영 모델 | 현재 API의 명시된 3.5 모델 계약 유지, 자동 교체 없음 | 모델 변경 또는 공급자 조건 재확인 필요 시 |
| 가림 방식 | 불투명 단색 덮기 제안, 원안의 모자이크 옵션은 결정 필요 | E1/E2 구현 전 |
| 게시본 보존 기간 | 무기한 보존·현재 7일 초안 정리 적용 모두 금지. 별도 만료값 필수 | E3 활성화 전 |
| 원본 공유 | 기본 꺼짐. 별도 경고와 opt-in 없으면 항상 차단 | F2 |
| 배포 비용·사이트 공개 수준 | 기존 공개 사이트 유지, 새 서비스/과금/익명 공개 자동 변경 없음 | R1/R2 |
| 모바일 범위 | 반응형 웹의 간단 제작 흐름, 네이티브 앱·오프라인 사본 미포함 | M1 착수 시 확인 |

가림 방식·보존 기간·운영 비용을 이 문서가 사용자 대신 승인한 것으로 취급하지 않는다. 계정 없는 현재 구조에서 edit token은 가이드 접근 권한이지 사람별 비용 한도나 신원 인증이 아니다.

## 8. 모든 단계의 완료 규칙

- 변경 전 현재 코드·문서·미커밋 변경을 확인하고 해당 묶음의 입력/출력·완료 조건을 정한다.
- 기존 구조를 확장한다. 보안/데이터 유실/비용 경합에 맞춘 계약·회귀 테스트를 작성하고, 변경 위험에 비례해 전체 검사를 실행한다.
- DB 변경은 추가 migration과 기존 데이터 호환을 검증한다. 실제 운영 DB에 파괴적 변경을 임의 적용하지 않는다.
- UI 작업은 화면·키보드/터치·오류/복구를 실제로 확인한다. 브라우저 확인 없이 타입/빌드 통과만으로 사용자 흐름을 완료 처리하지 않는다.
- 각 체크포인트에 변경 파일·검사 결과·남은 문제를 기록한다. 사용자에게는 구현한 것을 짧은 목록으로 설명한다. 푸시/배포는 별도 요청·승인 범위에 따른다.
- P0/P1 데이터 유실·권한·개인정보·비용 남용 문제가 남으면 다음 활성화 단계로 넘어가지 않는다.

## 9. 웹 1차 완성과 최종 검증

R2 진입 전, 합성 영상으로 녹화/업로드→분석→편집/새로고침→가림/게시→별도 기기 무로그인 보기→철회/전체 삭제까지 확인한다. 같은 요청 두 번, DB/저장소 일시 장애, AI timeout, worker 재시작, 처리 중 삭제가 있어도 중복 과금 예약·미가림 공개·다른 사용자의 데이터 노출·완료 허위 표시가 없어야 한다.

릴리스 기록에는 실행한 migration·앱 버전·모델/프롬프트/가격표 버전·한도·환경 검증·알려진 제한·복구 절차를 남긴다. 키·원본 파일명·이미지·프롬프트/공급자 원문은 기록하지 않는다. 장애 시 AI 신규 접수와 게시를 끄고, 호환되는 직전 앱으로 되돌리며, 불확실한 예산 예약과 삭제 기록은 보존한다.

운영에서는 준비 상태·대기 시간·실패 코드·토큰/예약·정리 지연을 확인한다. 기존 의존성 보안 기록은 과거 시점이므로 배포 전에 다시 점검한다. 실제 설명 상황 10건 중 7건 이상이 추가 질문 없이 수행에 성공하는지를 제품 가설로 평가한다. 처리 시간과 사람의 검토 시간을 따로 측정하며 ‘60초’는 검증 전 목표다.

이후 M1을 마치면 **PC 제작·모바일 간단 제작·모바일/PC 수신**이 같은 서버 데이터와 게시본을 사용하는 범위까지 완료다. 실패 평가에서 새 기능이 필요하면 이 계획에 무단 추가하지 않고 다음 버전으로 정한다.
