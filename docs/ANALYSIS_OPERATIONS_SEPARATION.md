# B5 변경 결정: 운영 확인과 요청별 자동 검사를 분리

2026-09-19. 사용자는 다음 차이를 설명받은 뒤 `ㄱㄱ`로 설계 변경·구현을 승인했다.

- 요청마다 앱이 집행하는 소유권·동의·승인 합성 자료·목적지·한도·중복 방지 검사는 유지한다.
- 플랫폼 저장소 권한·과금·계정 조건은 운영자가 근거를 확인하는 별도 절차로 나눈다.
- 이 방식은 계정/플랫폼 변경을 즉시 자동 감지한다는 보장을 제공하지 않는다.
- 미확인은 통과가 아니다. 개인 영상 외부 전송, AI 활성화, 과금·권한 변경, 공개 배포는 이번 승인 범위가 아니다.

원본 개발 계획과 `ANALYSIS_READINESS.md`의 이전 요구/진행 기록은 수정하지 않는다. 이 문서가 **승인된 후속 변경**을 기록한다. 과거의 `verified-free-project`, `replit-private`, `hostingAllowance: verified`를 실제 구현 없이 자동 증명으로 취급하는 계약을 제거했다. 이전 자동 증명 형태로 되돌아가는 fallback은 없다.

## 구현된 경계

| 분류 | 의미 | 유효기간/변경 처리 |
|---|---|---|
| 런타임 확인 | 현재 앱 DB·실행기·계수 원장·Replit 저장소 연결 식별자·앱의 프로젝트 단위 원자적 차감 | 최대 30초, 기존 만료·취소·시간 역행·날짜 경계·철회 검사 유지 |
| 승인 입력 | 정확한 영상 manifest, 합성 입력 승인, 전체 요청의 검토된 토큰 상한 | 기존 최대 30초 계약 유지. 이 변경으로 상한을 추정하거나 승인하지 않음 |
| 운영 기록 조회 | 인증된 운영 기록의 현재 버전/철회 상태를 읽었다는 사실 | 조회 스냅샷은 최대 30초. 클라우드 사실을 방금 확인했다는 뜻이 아님 |
| 운영자의 관측 | 저장소 접근, 무료 프로젝트, 공급자 한도, 호스팅 예산, 프로젝트 내 다른 전송자 확인 | 관측 원래 시각 보존, 명시된 만료에 종료. 새 조회로 연장하지 않음 |

`analysis-operations-review.ts`의 운영 기록에는 다음이 필요하다.

- 확인자 참조, 기록 ID/버전, 작성 시각, 만료 시각.
- 같은 배포·Google 프로젝트·키 버전·Replit 저장소 참조와 모델·앱 예산 정책.
- 다섯 항목 각각의 상태(`unknown`/`rejected`/`confirmed`). `confirmed`는 관측 시각과 내부 근거 참조가 필수다.
- `approved_synthetic`, `free_only`, 유료 fallback 금지, `operator-recheck-required` 명시.

승인된 기록이고 다섯 항목 모두 확인돼야 한다. 빈 값, 누락, 거절, 미확인, 대기, 철회, 다른 연결 대상, 잘못된 시각은 거절한다. 근거 참조는 경로/URL/키/개인정보 원문 대신 제한된 내부 식별자다. 문자열 형식 통과는 그 근거의 진실성이나 작성자 권한을 증명하지 않는다.

### 운영 확인의 의미

- `storageAccess`: 대상 버킷의 지원되는 권한 확인 근거가 필요하다. 앱에서 인증 없는 요청이 거절됐다는 시험, 버킷 ID, 프로젝트 협업자 목록만으로 버킷 권한 전체를 확인했다고 하지 않는다.
- `freeProject`: 지정 프로젝트와 현재 키의 소속, 무료 전용/결제 상태를 확인한 관측이다. API 키가 작동하거나 과거 호출이 성공했다는 사실로 대체하지 않는다.
- `providerLimits`: 해당 모델의 프로젝트 한도와 단위를 기록한다. 현재 잔여량·가용량 보증이 아니다.
- `hostingBudget`: 승인된 개발/운영 환경의 저장·트래픽·호스팅 과금 범위와 한도를 확인한다. 총비용 0 보증이 아니다.
- `projectSenders`: 다른 키·도구·프로세스를 포함한 프로젝트 사용 통제 범위를 확인한다. 앱 원장은 자신을 거친 전송만 원자적으로 차감하며 외부 전송자를 자동 통제하지 않는다.

### 기간과 재확인

이번 개발용 구현의 운영 기록 최대 기간은 **가장 오래된 항목 관측부터 24시간**으로 제한한다. 공급자의 보증 기간이나 사용자가 기존 MD에 지정한 수치가 아니라, 무기한 승인을 막기 위한 구현상 상한이다. 더 짧은 만료를 지정할 수 있다. 24시간 동안 설정이 그대로라는 뜻이 아니며, 운영자는 변경을 알게 되는 즉시 철회·재검토해야 한다.

다섯 관측보다 앞선 작성 시각, 미래 시각, 만료된 기록을 거절한다. 오래된 관측을 그대로 둔 채 기록 시각/조회 시각만 바꿔 만료를 연장할 수 없다. 운영 기록은 날짜 경계만으로 새 관측이 되지 않는다. 새 날짜에 요청을 진행하려면 런타임/입력/기록 조회의 짧은 스냅샷은 다시 받아야 한다.

## 기존 실행 경로에 연결한 검사

`EvidenceAnalysisReadiness`는 기존의 가상 무료 검증기 대신 `operations` 소스로부터 현재 운영 기록을 받는다. 소스는 여전히 기본값이 없고, 하나라도 없으면 `ANALYSIS_UNAVAILABLE`다. 운영 기록을 HTTP 본문이나 환경 JSON으로 받거나 항상 참인 검증기로 감싸는 경로는 추가하지 않았다.

운영 기록과 런타임의 배포·프로젝트·키 버전·저장소가 모두 일치해야 한다. 운영 기록/정책 변경이나 철회는 전체 레코드를 비교하는 소스 검사와 `clear()`로 기존/진행 중 스냅샷을 무효화한다. `isCurrent`는 원격 계정의 실시간 불변이 아니라 앱에서 관측한 상태와 운영 기록 버전/철회를 확인한다.

무료 전용 접수 스냅샷에는 `operationsBasis`가 필수다. 운영자 확인임을 표시하고 원래 관측/작성/만료 시각을 보존한다. 이 메타데이터는 내부 검사에만 쓰며 사용자 HTTP 응답에 노출하지 않는다.

접수/저장 직전과 실제 계수·생성 전송 시 사용하는 공통 검증기가 이 출처·유효기간을 재검사한다. 짧은 실행 스냅샷은 운영 기록 만료를 넘을 수 없다. 운영 근거가 없는 예전 무료 스냅샷은 거절한다. 모의 검사 전용 유료 계약은 유지했지만 이번 구성기는 여전히 무료/합성 입력만 만들 수 있고 제품의 유료 전환을 열지 않는다.

## 하지 않은 것과 다음 의존성

**이것은 분리 계약과 실행 검사 구현 완료이지 실제 AI 실행 준비 완료가 아니다.**

1. 인증된 운영 기록의 영속 저장·작성/철회 권한·프로세스 간 버전 동기화와 실제 런타임 소스는 아직 연결하지 않았다. 원격 변경을 즉시 감지한다고 주장하는 더미 검증기를 만들지 않는다. 과거 UI 확인을 현재 승인 기록으로 자동 발급하지 않았다. 실제 버킷 권한의 미확인 상태도 그대로다.
2. 전체 요청의 신뢰 가능한 입력 상한은 여전히 미확정이다. 과거 7,199토큰을 다른 입력에 적용하거나 이미지 바이트/개수로 보증하지 않는다. `countTokens`도 외부 이미지 전송이므로 기존 별도 계수 원장과 사전 허가를 유지한다.
3. 그 후에만 승인된 합성 입력을 대상으로 접수·계수·생성·취소·복구의 실제 실행 연결을 검증할 수 있다. 서버 시작 실행기 등록, 사용자용 capabilities 활성화는 이번에 하지 않았다.

사용자 영상/초안 접근, AI 호출, 클라우드 DB/Storage 변경, Secrets/계정 권한/과금 설정 변경, Replit 재시작, 공개 배포는 하지 않았다. 기존 녹화·선택·장면 추출·편집·자동 저장 UI는 변경하지 않았다.

## 검증 기록

- 변경부 단독 검사 78개 통과, 실패·생략 0. 운영 관측 시각 유지, 다섯 미확인 항목 거절, 만료·철회·다른 배포/키/저장소, 날짜 경계, 개인 입력/상한 누락 차단, 접수 전 상태 불변, 계수 최종 전송 거절을 확인했다.
- API 테스트 TypeScript 검사 통과(실제 PostgreSQL 검사 소스 포함).
- 최초 검사에서 새 `operations` 필드와 기존 비동기 작업 변수의 이름 충돌을 발견했다. 작업 변수명을 `inspections`로 고친 뒤 위 검사를 통과했다. 안전 조건/시간 제한을 완화하지 않았다.
- 최종 일반 전체 회귀 **782개(이관 91 + 서버 605 + 클라이언트 86)**, 실패·생략 0, 종료 코드 0. 기존 격리 실행기로 앱 환경/비밀값을 제외했으며 기존 테스트용 FFmpeg/ffprobe 경로만 사용했다. 테스트 제외·미디어 시간 제한 변경·사전 예열은 하지 않았다.
- API 제품/테스트 TypeScript 검사와 서버 빌드 통과. 빌드는 Windows 상위 경로 접근에 필요한 권한으로 실행했으며 서버를 시작하지 않았다. 프런트엔드 코드는 바꾸지 않았고 프런트엔드 빌드는 이번에 다시 실행하지 않았다.
- 실제 PostgreSQL 재검사는 **미실행**이다. 사용자별 기존 Docker CLI를 찾았지만, 로컬 `dockerDesktopLinuxEngine` 파이프가 없어 엔진 연결에 실패했다. Docker 시작/재설정·설치·이미지 다운로드·DB/컨테이너 생성은 하지 않았다. 기존 70개 통과 기록을 이번 결과로 재사용하지 않는다. 변경한 PostgreSQL 통합 검사 fixture는 타입 검사에 포함됐다.
- 위 숫자는 현재 클라우드 권한·무료 상태·개인정보 안전의 증명이 아니라 로컬 합성/모의 검사 결과다. 이번 변경은 로컬 작업본에 있으며 커밋/푸시·Replit 반영·실제 운영 기록 발급은 하지 않았다.

위 검증/미구현 항목은 분리 계약 단계의 당시 기록이다. 사용자가 Docker 실행 완료를 알려준 뒤 내부 운영 기록 저장·철회와 공유 중지 처리를 구현하고 실제 임시 PostgreSQL 80개 검사를 통과했다. 세부 권한 경계, 검증 결과와 아직 연결하지 않은 부분은 [운영 기록 저장 후속 기록](ANALYSIS_OPERATIONS_STORE.md)에 남겼다. 운영 서버 반영이나 AI 활성화 완료를 뜻하지 않는다.
