## 이번 구현

### 1. 전송보다 먼저 저장되는 공급자 한도

`PostgresAnalysisQuotaStore`는 기존 전체 분석 제어 잠금을 사용해 같은 프로젝트/모델의 RPM·입력 TPM·태평양 RPD를 검사하고 고유 요청 차감을 확정한다. 이 트랜잭션이 **COMMIT된 다음에만** 가이드·취소·소유권을 검사하는 읽기 전용 전송 잠금으로 들어간다. 전송 후 DB 롤백으로 차감이 사라지는 구조를 피한다. 공급자 응답을 기다리며 DB 잠금을 유지하지 않는다.

- 새 `0008_analysis_provider_quota.sql`: 가이드 FK 없는 최소 원장. 프로젝트/요청 식별자는 SHA-256으로 묶고 원본 이미지·편집 키·API 키·파일 경로는 저장하지 않는다. 보존 기록을 자동 삭제하거나 실패/취소 후 환불하지 않는다.
- 같은 요청은 한 번만 차감한다. 중복·재시작·저장 응답 유실 뒤 같은 요청의 허가를 재발급하지 않는다. 재시도는 기존에 허용된 별도 요청 차수에만 새 차감이 생긴다.
- 허가는 최대 5초, 준비 보고서 만료 또는 태평양 자정까지 중 더 이른 때에 끝난다. 분당 사용량은 **차감 시점이 아니라 실제로 전송할 수 있는 마지막 순간**까지 보수적으로 잡는다. 잠금 대기 때문에 한도가 너무 일찍 풀리지 않는다.
- 최종 잠금에서 DB 시각과 허가를 비교한다. 실제 호출 콜백에서도 다시 검사하며, DB 시각 조회 후 흐른 시간은 단조 시계를 사용해 보수적으로 더한다. 인계·취소·삭제·전체 중단·만료는 전송을 막는다.
- DB 원장 쓰기 실패/늦은 철회는 롤백한다. 차감은 확정됐지만 뒤에서 취소되거나 성공 응답을 못 받으면 차감은 남긴다. 실제로 안 보냈더라도 최대 사용량이 보존되는 보수적 동작이다.
- 일일 앱 예산은 기존 UTC 원장이다. Google 공급자 제한은 별도다. 현재 한도 부족은 해당 분석을 안전하게 중단시키며, 자동 대기·다음 분 재개 UI는 추가하지 않았다.

기존 PostgreSQL 구조·JSON v5·모델·외부 전송 형식은 유지한다. 접수 준비 보고서의 DB 요구 버전만 `postgres-0008`로 올렸다. 신규 quota store와 입력 검증기가 없는 dispatcher는 `disabled`, 기본 새 분석 POST는 계속 503이다. 시작 코드에는 새 store/loader/verifier를 연결하지 않았다.

### 2. 전체 입력의 내용 식별과 상한 근거 검사

`auditGeminiInput`는 로컬에서 실제 요청을 구성해 모델·시스템 프롬프트·응답 schema·메타데이터·대상/문맥 이미지 **전체 내용**의 fingerprint를 만든다. 바이트 수와 이미지 수만 반환하며 원본/프롬프트/인라인 이미지 문자열은 기록하지 않는다. 문맥 이미지 한 바이트가 바뀌어도 fingerprint가 달라진다.

`AnalysisInputBoundVerifier`는 별도 신뢰 어댑터 계약이다. 검사기는 **정확히 같은 요청·입력 승인·모델/프롬프트**에 대한 전체 토큰 상한 근거만 받아들인다. 시스템·schema·메타데이터·대상·문맥·구조 오버헤드를 모두 포함해야 하며 기존 예약 상한보다 커서는 안 된다. 근거는 최대 30초이고 철회/만료/UTC·태평양 날짜 변경/비동기 참값을 거절한다. 실제 전송 직전에도 재검사한다.

**실제 상한 근거를 발급하는 어댑터는 아직 없다.** 테스트의 1,000 토큰 근거는 의도적인 가상 자료다. JSON 필드 이름이나 과거 성공 응답을 운영 증명으로 사용하면 안 된다. `inspect`가 Google로 이미지를 보내거나 `countTokens`를 몰래 호출하는 것도 허용하지 않는다.

## 공식 문서 검토와 남은 상한

- Google의 Gemini 3 미디어 설명은 기본 이미지 처리량을 약 1,120 토큰으로 안내한다. 그래서 6장 보고서에는 **이미지 부분 추정 6,720**을 표시하지만, 이것은 전체 요청 상한이 아니다. 보고서의 `verifiedInputTokenUpperBound`는 계속 `null`이다. [미디어 해상도·토큰 표](https://ai.google.dev/gemini-api/docs/media-resolution)
- 시스템 지침도 입력 토큰에 포함되며, `countTokens`는 입력에 대한 별도 API 호출이다. 문서의 일반 이미지 타일 계산만으로 현재 모델의 모든 입력 비용을 확정하지 않는다. [토큰 안내](https://ai.google.dev/gemini-api/docs/tokens)
- 선택 모델의 1,048,576 입력 토큰 한도는 모델이 수용하는 문맥 크기다. 우리 요청의 실제 토큰 수·무료 프로젝트의 분당 여유와 동일하지 않다. [3.5 Flash-Lite 모델 사양](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)
- RPM·TPM·RPD는 프로젝트 단위다. **이 원장을 우회하는 다른 키/앱/독립 smoke 호출의 사용량은 자동 조회하지 않는다.** 전체 전송자를 포함하거나 별도 사용을 차단하는 근거가 있어야 운영 활성화할 수 있다. [비율 제한](https://ai.google.dev/gemini-api/docs/rate-limits)

다음 B5-B3b2는 이 근거를 어떻게 얻고 갱신할지 확정하는 단계다. 실제 계정/키 소속·합성 입력 승인·모델별 전체 입력 근거를 묶어야 한다. 제한 `countTokens`/합성 분석이 필요하면 전송 대상·요청 수·무료 조건을 확인하고 별도 실행 승인 후 한다. 한 번의 실측을 모든 이미지에 대한 수학적 상한이라고 표현하지 않는다. 기존 성공 이미지 2장을 최대 6장·모든 문맥의 상한으로 확대하지 않는다.

## 검증 범위

최종 `npm run check`: **processor 405 + client 4 = 409개**, 실패/건너뜀 0, 타입 검사·processor 빌드·린트·Site 빌드 통과. 이전 단계 대비 기본 시험 20개(차감 8, 입력 근거 6, dispatcher 6)를 추가했다. 실제 토큰 근거와 공급자 응답은 가상이고 네트워크 전송은 하지 않았다. 기존 Vite 설정/라우트 자동 분류 안내는 남는다.

별도 `processor:postgres:verify`: **실제 PostgreSQL 16.15 23/23개 통과**, 기존 17개 + 신규 6개다. 새 시험은 20개 독립 연결의 한도 경합, 중복 차감/재연결/삭제 보존, 쓰기 오류/철회 롤백, 잠금 대기 후 취소/전체 중단, 확정 영수증의 전송 시점 검사, 잘못된 수치/시각/날짜 SQL 제약이다. migration `0000–0008` 적용·재적용을 확인했다. 합계 **432개**이며 같은 시험의 반복 실행은 중복 합산하지 않는다.

새 migration·Drizzle 스냅샷·스키마를 대조했고 다시 생성 확인했을 때 추가 변경이 없었다. `git diff --check`를 통과했고 실제 키가 소스/문서에 포함되는지는 값 출력 없이 검사했다.

실제 DB는 기존 PostgreSQL 16.15 이미지를 이용한 고유 이름의 폐기용 컨테이너이며 loopback·tmpfs만 사용한다. 새로 만든 시험 DB/컨테이너는 정리하고 기존 사용자 DB/컨테이너는 유지한다. 운영 DB·클라우드 저장소·Gemini 호출·과금 설정 변경·푸시·배포는 하지 않았다. DB 네트워크 강제 단절/진짜 COMMIT 응답 유실/서로 다른 worker 프로세스 장애를 검증한 것은 아니다.
