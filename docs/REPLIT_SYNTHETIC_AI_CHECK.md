# Replit → Gemini 합성 화면 실호출 확인

2026-09-18. **개발용 독립 시험은 성공했다. 제품 자동 분석 연결이나 B5 전체 완료는 아니다.**

## 승인과 대상

사용자는 영상/추출 화면의 Gemini 전송 의미를 설명받은 뒤 “만들기 위해서는 전부 해봐야겠지 진행해”라고 요청했다. 실행 범위는 개인정보 없는 내장 합성 화면의 입력량 계산 1회와 설명 생성 1회로 좁혀 알렸다. 실제 개인 녹화물 전송·유료 전환·모델 변경·제품 자동 활성화·공개 배포는 하지 않았다. 이전 시험 승인을 재사용하지 않았다.

기존 SHOW-ME Replit Shell에서 프로젝트 식별자, clean 작업본, 커밋 `63d59e8d3ed1f30516b5d25d4de210ef31c19db7`를 검사했다. 코드가 고정 생성한 640×360 `SETUP / NEXT`, `READY / DONE` 화면 두 장을 육안 확인했다. 이를 6개 프레임 위치(대상 4 + 문맥 2)에 사용하는 기존 진단 도구만 실행했다. 사용자 파일·화면 캡처·저장소 영상·초안은 입력하지 않는다.

키의 프로젝트 일치·무료/결제 미설정·모델 한도는 앞선 같은 날 UI/프로세스 확인을 근거로 사용했다. 원문 키를 출력·복사하거나 명령에 넣지 않았으며 기존 Shell 환경의 키를 Google API 인증에만 사용했다. 이 일회 점검은 자동 과금 증명이나 변경 즉시 감지 기능이 아니다.

## 실제 결과

| 항목 | 확인 결과 |
|---|---|
| 모델 | `gemini-3.5-flash-lite` |
| 전송 전 준비 검사 | `prepared-not-sent`, `networkCalls: 0`, 과거 고정 합성 요청과 지문 일치 |
| `countTokens` | `counted-synthetic-only`, 1회, **7,199 입력 토큰** |
| `generateContent` | `generated-synthetic-only`, 1회, **7,199 입력 토큰 / 사고 포함 425 출력 토큰** |
| 요청 일치 | 같은 전체 요청 지문, 계산/생성 입력량 차이 0 |
| 출력 검증 | 엄격한 서버 출력 스키마 통과, 대상 ID 순서대로 한국어 4단계 |
| 좌표 | 네 단계 모두 x=50%, y=68.8%; 640×360 화면에서 합성 버튼 내부 |
| 저장 | `resultSaved: true`; 결과 파일 수정 시각 `2026-09-18T11:29:29.759Z` |
| 제품 자동 분석 | `enablesAnalysis: false` 유지 |

생성된 안내는 순서대로 “완료 버튼을 누르세요.”, “다음 버튼을 누르세요.”, “완료 버튼을 누르세요.”, “다음 버튼을 누르세요.”다. 반복 합성 화면의 순서와 맞는다. 복잡한 실제 작업 절차의 품질을 검증한 것은 아니다.

전송 목적지는 Google의 `generativelanguage.googleapis.com` 모델별 `countTokens`와 `generateContent`다. 자동 재시도·모델 fallback은 없었고 각 CLI의 하루 1회 예약 기록을 유지했다. 두 요청만 실행했으며 결과 재확인은 저장된 합성 JSON만 읽었다. 제품/API 서버는 다시 시작하지 않았다.

## 보관과 한계

- Replit의 `artifacts/api-server/src/.data/gemini-token-probe/2026-09-18/attempt.reserved`, `gemini-generation-probe/2026-09-18/attempt.reserved`와 `result.json`을 유지한다. `.data/`는 Git 제외다. 재실행을 위해 예약 기록을 지우지 않는다.
- 실행 뒤 `git status --short --branch`에는 변경 파일이 없었다. 새 키·권한·결제·서버 설정·DB/Storage 데이터를 변경하지 않았다. 이번 외부 요청은 내장 합성 화면만 전송했다.
- 개인정보 후보는 0개였지만 애초에 개인정보가 없는 자료다. 개인정보 탐지율·가림 품질 검증이 아니다.
- `verifiedInputTokenUpperBound: null`, `projectVerifiedAutomatically: false`를 유지한다. 7,199라는 단일 실측을 다른 요청의 상한이나 실환경 readiness로 발급하지 않는다.
- 이번에 기본 앱 접수/실행기의 거절 조건을 우회하거나 완화하지 않았다. 독립 진단 성공을 앱의 업로드→AI→초안 저장 전체 흐름 성공으로 표시하지 않는다.
- 제품/테스트 코드를 바꾸지 않았고 전체 회귀를 재실행하지 않았다. 실제 시험 결과와 남은 조건을 로컬 MD에만 기록했으며 커밋/푸시하지 않았다.
