## 격리 환경

- 기존 Docker Desktop과 로컬 PostgreSQL 이미지를 사용했다. 설치·이미지 다운로드·클라우드 DB·과금 변경 없음.
- 실제 엔진: PostgreSQL **16.15** (Debian). 이미지 ID: `sha256:f1c3376c26f2609ab9f29f71f824103fe2fcd8ee0346485cb6122a4f93df6f94`.
- 매 실행마다 무작위 이름의 `showme-b5-…` 컨테이너를 생성하고 127.0.0.1의 임의 포트만 열었다. CPU 1개·메모리 512 MiB·tmpfs 데이터 256 MiB, 호스트 폴더/기존 DB 연결 없음.
- 각 시험은 무작위 이름의 새 DB와 최대 25개 연결 pool을 사용한다. 실제 SQL 잠금·대기·확정·롤백·제약을 확인했으며 DB 대역을 사용하지 않았다.
- `.env`/앱 `DATABASE_URL`/AI 키를 사용하지 않는다. 입력·출력·가격은 가상이고 전송 콜백은 숫자만 센다. Google 호출 없음.
- 고유 이름·소유 라벨을 확인한 후 시험 DB/컨테이너/tmpfs를 정리했다. 폐기용 자료이며 재실행으로 재생성할 수 있다. 사용자 자료나 기존 컨테이너는 삭제하지 않았다.

## 통과한 17개 시험

1. migration `0000–0007` 실제 적용·재적용, 중단 제어 보존.
2. 20개 동시 접수에서 실행·예약·두 일일 집계가 한 번만 생성됨.
3. 서로 다른 가이드의 20개 동시 인수에서 전체 유효 소유권이 한 개만 생김.
4. 중복 정산 20개와 종료 정리 20개에서 예산이 한 번만 반환됨.
5. 묶음 결과·정산·최종 초안의 원자 확정과 중복 완료 재반영 방지.
6. DB trigger로 결과 저장을 실패시켜 결과·초안·원장·예산 전체 롤백 확인.
7. 실제 guide 잠금에 취소를 먼저 대기시킨 뒤 뒤따르는 launch의 전송 횟수 0 확인.
8. launch 콜백에서 취소를 시작해도 잠금이 풀리고 취소가 완료됨. 실제 네트워크 지연 시험은 아님.
9. 삭제 cascade로 비공개 자료는 제거하고 불확실 수치 원장·종료 정리는 유지됨.
10. 전날 queued 작업 안전 종료와 새 요청의 오늘 예산 확보.
11. 실제 21개 가이드의 keyset 조회가 20개+1개를 중복/누락 없이 반환함.
12. 다른 DB 연결의 저장소가 저장된 503 근거·만료 소유권을 인수해 재시도 슬롯을 이어감.
13. 조회 열/payload 불일치와 미종료 예약의 잘못된 반환 값을 SQL 제약이 거절함.
14. 사용량 상한 초과가 신규 접수를 차단하고 종료·삭제·새 연결 후에도 중단과 최대분이 유지됨.
15. 실제 DB 잠금 대기 중 lease가 만료되면 뒤늦은 launch를 차단함.
16. 종료 정리의 마지막 쓰기를 trigger로 실패시켜 실행 종료·예산 반환·불확실 변환 전체 롤백 확인.
17. `0004` 형식의 최소 SQL payload를 `0005–0007`로 바꾸면서 조회 열과 최대 예약을 보존함.

첫 14개 통과 후 세 경계 시험을 추가해 **17/17, 실패/건너뜀 0**을 확인했다. 마지막 DB 시험 시간은 약 8초다. 기본 `npm run check`도 **356 processor + 4 client = 360개**, 타입·lint·빌드 통과. 합쳐 **377개**다. DB 시험은 기본 check에 자동 포함하지 않고 타입 검사에만 integration 파일을 포함한다.

## 재실행

Docker가 실행 중이고 로컬 `postgres:16` 이미지가 있어야 한다. 이 PC에서 확인한 경로:

```powershell
$env:SHOWME_TEST_DOCKER_BIN = 'C:\Users\fxxkm\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe'
$env:SHOWME_TEST_DOCKER_HOST = 'npipe:////./pipe/dockerDesktopLinuxEngine'
npm run processor:postgres:verify
```

환경값은 해당 셸에서만 사용하고 `.env`에 저장하지 않는다. 다른 PC는 실제 Docker 실행 파일 위치를 지정한다. 원격 엔진/임의 기존 DB URL은 허용하지 않으며 이미지를 다운로드하지 않는다. 오류에는 임시 암호·연결 문자열을 출력하지 않는다. 호스트 강제 종료로 자동 정리가 실패하면 출력된 정확한 시험 컨테이너와 라벨을 확인해 정리한다. 기존 Docker 볼륨이나 DB 전체를 지우지 않는다.
