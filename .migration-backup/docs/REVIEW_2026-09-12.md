# ShowMe Gate 0–2 독립 리뷰

검토일: 2026-09-12. 범위: 초기 커밋 이후의 미커밋 Gate 0–2 구현과 마지막 timeout/삭제 경합 변경.

## 확인하고 수정한 문제

1. **P1 — 오래된 worker가 새 attempt의 삭제를 완료함.** `processClaimed` 진입과 실패 정리 경로가 삭제 대기 여부만 검사해 새 작업의 원본과 durable row까지 삭제할 수 있었다. 이전 worker를 새 attempt의 ACTIVE 삭제 상태에서 실행한 회귀 테스트로 행과 원본 소실을 재현했다. worker/업로드 lease별 소유권을 최종 정리 전후에 확인하고, 늦은 저장 정리에도 같은 조건을 적용했다.
2. **P1 — 자동 정리가 갱신된 생존 신호를 무시함.** 오래된 목록 snapshot을 선택한 다음 heartbeat가 갱신돼도 삭제가 진행됐다. 선택 직후 heartbeat를 갱신하는 회귀 테스트에서 실제 삭제 호출을 확인했다. `expectedUpdatedAt`을 JSON/PostgreSQL 상태 변경·삭제에 추가하고, 정리 시작 및 마지막 DB 삭제 시 다시 검사한다.
3. **P2 — 미구현 분석을 완료된 것으로 표시함.** 실제 영상 검토 화면에 AI 초안과 개인정보 탐지 완료 문구가 있었고, 재생성 버튼은 고정 문구만 넣었다. 실제 영상은 추출 단계임을 표시하며 AI 재생성·가림 편집을 비활성화했다. 개인정보 미가림과 새로고침 시 편집 유실을 모바일에서도 보이는 안내로 명시했다. 실제 영상의 공개 차단은 유지한다.
4. **검증 결함 — 늦은 저장 테스트가 끝나지 않음.** 저장 작업을 시작하기 전에 abort해서 이후 삭제 완료를 무한히 기다렸다. 5초 제한을 둔 실행으로 재현했고 실제 SDK 쓰기 시작 신호를 기다린 다음 중단하도록 고쳤다.

## 추가 확인

- 시간 초과된 프레임 저장 → HTTP DELETE 202 → 늦은 저장 완료 → 첫 후속 삭제 실패 순서에서도 durable ACTIVE 기록과 자산이 남아 재정리되는 통합 회귀 테스트가 통과한다.
- 삭제가 멈춘 행이 배치 선두를 독점하지 않고 후속 가이드가 다음 정리 주기에 삭제된다.
- 업로드 lease 갱신과 자동 정리의 경합에서 갱신된 업로드가 보존된다.
- 현재 단계는 FFmpeg 장면·프레임 추출까지이며 AI·편집 저장·비가역 가림·공개 링크는 후속 단계다.

## 검증 범위와 제한

회귀 검증은 로컬 JSON/파일 어댑터, 실제 FFmpeg fixture 및 실패 주입을 사용한다. PostgreSQL/Replit App Storage 실서비스에서의 경합·롤링 배포·장애 복구와 실제 브라우저 화면 공유 권한은 별도 검증 대상이다. 공개 사이트는 갱신하지 않았다.

최종 검증 결과:

- `npm run check` 통과: 프로세서 테스트 83개, 클라이언트 테스트 4개, 프로세서 타입 검사·빌드, 전체 린트, 사이트 프로덕션 빌드.
- `npx tsc --noEmit --incremental false` 통과: 프런트엔드 TypeScript 별도 검사.
- `git diff --check` 통과. Windows 줄바꿈 변환 경고만 있다.
- `npm audit --omit=dev --audit-level=high` 통과: high/critical 0개. Replit 저장소 SDK의 전이 의존성에서 moderate 6개가 남아 있으며 자동 수정 가능 항목은 없다.
- 로컬 사이트 HTTP 200과 프로세서 `/health` 200 확인. 브라우저에서 초기 화면 및 화면 녹화 버튼을 확인했다.
- 브라우저 자동화의 파일 선택 이벤트가 시간 초과되어 실제 업로드부터 검토 화면까지의 수동 종단 검증은 완료하지 못했다. 업로드 API·실제 FFmpeg·실패 복구는 위 자동 테스트로 검증했다. 실제 화면 공유 권한 및 녹화는 사용자의 브라우저에서 추가 확인해야 한다.

운영 배포와 Gate 3 이상의 구현은 이 검증에 포함하지 않는다.
