# Gate 3A — AI 계약·저장 기반 체크포인트

작성일: 2026-09-12 · 기준: [순차 구현 설계](NEXT_PHASE_DESIGN.md)

후속 변경: 사용자가 Gemini를 선택하여 Gate 3B-1 어댑터와 가상 화면 시험을 추가했다. 아래는 3A 시점 기록이며, 현재 범위·실호출 미검증 사항은 [Gemini 설정 안내](GEMINI_SETUP.md)를 참고한다.

## 이번 단계에서 구현한 것

- AI 응답의 단계 소속·누락·중복·텍스트 길이·좌표·가림 영역 끝점·알 수 없는 행동·마지막 단계 병합 여부를 검증한다. 알 수 없는 클릭 위치는 null이고 새 초안에 임시 중앙 포인터를 만들지 않는다.
- 서버의 실제 미디어 attempt, 프레임 위치·크기·저장 키를 fingerprint로 묶는다. AI에 전달할 manifest에는 저장 키·원본 이름·편집 키가 없다.
- 최대 24프레임을 4개 분석 대상 + 앞뒤 문맥 최대 2개로 나눈다. 이미지 1장당 2 MiB 제한을 적용한다.
- 미디어 상태와 분리된 분석 실행 및 초안 revision을 저장한다. 최초 결과만 미수정 revision 0에 자동 채택하며, 사용자 수정이 있으면 결과를 제안으로만 보존한다.
- 동의 버전·실행 ID·공급자/모델/프롬프트 버전·attempt 번호를 기록한다. 중복 시작·동시 소유권·재사용한 attempt ID·취소·입력 변경·삭제 후 응답을 차단한다.
- JSON과 PostgreSQL이 같은 상태 전이 함수를 사용한다. PostgreSQL 변경은 부모 guide 행 잠금 안에서 처리하고, 새 두 테이블은 guide 삭제 시 cascade된다. JSON의 구형 v1 파일은 추가 필드 없이도 읽을 수 있다.
- 테스트 전용 공급자와 내부 실행기로 성공·거절·불완전 응답·잘못된 응답·시간 초과·늦은 응답·이미지 과대 입력을 시험한다. 결과·사용량·제한된 오류 코드만 저장하며 공급자의 원문 오류나 이미지 바이트는 저장하지 않는다.
- 원본 미디어/프레임은 수정하지 않는다. 분석 모듈은 현재 서버 시작·업로드 파이프라인·웹 API·화면에 연결되어 있지 않다. 가짜 AI를 실제 기능처럼 표시하는 모드는 없다.

## 저장 구조와 적용 범위

- 추가 migration: `processor/drizzle/0002_analysis_foundation.sql`.
- `guide_drafts`: guideId, revision, inputFingerprint, 편집 문서, 생성/수정 시각.
- `analysis_runs`: guideId + runId 복합 키, 상태, 실행 metadata와 검증된 결과의 JSON payload. 가이드당 실행 기록 최대 12개, 실행당 claim 최대 3개.
- migration 생성·SQL 검토만 수행했다. 실제 운영 DB에 적용하지 않았다. 향후 dispatcher 검색 인덱스·lease heartbeat·실행 내 실패 묶음 재시도·예산 예약은 Gate 3B에서 추가한다.
- 초안은 현재 privacyReview가 pending인 상태만 허용한다. 검토 완료·게시·가림 이미지 생성 기능은 포함하지 않는다.
- 내부 `save-draft` 명령은 revision 경합 검증을 위한 기반이다. 사용자용 저장 API의 mutationId 재전송 처리·편집 명령·접근 제어 연결은 Gate 4 범위다.
- media fingerprint가 바뀐 기존 초안은 자동 초기화하거나 덮어쓰지 않고 거부한다. 재추출된 미디어에 대한 명시적 새 초안 생성 정책은 실제 재처리 UX와 함께 추가한다.
- 실행 중인 가이드를 삭제하면 추가 AI 결과 적용이 차단되고 분석/초안 행도 삭제된다. 이미 공급자에 전송된 데이터 회수나 외부 API의 즉시 중단을 보장하는 기능은 아니다.

## Gate 2 보완 확인

자동 연결 검증을 추가했다. 개인정보 없는 1초 MP4/MOV/WebM을 각각 생성해 실제 multipart 업로드, 실제 FFmpeg, 인증된 조회, 티켓 이미지 조회, 미인증 접근 차단, 초안 생성, HTTP 전체 삭제, 기존 이미지 티켓 재접근 차단을 시험한다.

이 결과는 브라우저 화면 선택/직접 녹화 검증을 대체하지 않는다. 실제 브라우저 권한 선택은 아직 사람이 확인해야 하며, 아래 표는 통과 처리하지 않았다.

| 실제 브라우저 항목 | 상태 |
|---|---|
| 창/탭/전체 화면 선택과 녹화 시작 | 미검증 |
| 권한 거절·선택 취소 | 미검증 |
| 브라우저에서 공유 종료 | 미검증 |

| 카카오톡/모바일 내부 브라우저 | 미검증 |

## 검증 결과

- `npm run check`: 성공. processor 테스트 122개와 client 테스트 4개, 총 126개 통과(실패·취소·건너뜀 없음). processor 타입 검사·빌드, lint, frontend production build도 통과했다.
- `npx tsc --noEmit --incremental false`: 성공.
- 기존 processor 테스트 83개에 계약·저장·실행·실제 업로드 연결 검증 39개를 추가했다.

로컬 테스트는 JSON 저장소·공통 상태 전이 함수·가짜 AI·실제 FFmpeg를 사용한다. **PostgreSQL 행 잠금·트랜잭션·cascade의 실제 DB 통합 검증은 아직 하지 않았다.** 실제 DB/저장소 검증은 해당 환경을 준비한 뒤 수행하며 로컬 성공과 구분한다.

## 다음 단계와 비활성 상태

다음은 Gate 3B다. 실제 공급자 어댑터, 구조화 출력용 JSON schema, 요청별 timeout/retry, API 인증·동의, 별도 dispatcher, 비용 예약·일일 한도, 실패 묶음 보존/재시도를 연결한다. 현재는 전체 실행 성공 시에만 결과를 저장하며 부분 성공 묶음 재사용은 아직 없다.

키·이용 가능한 모델 snapshot·가이드/일일 예산이 정해지지 않은 상태에서는 유료 실호출을 켜지 않는다. 실제 이미지 전송 전에 외부 AI 처리 안내·동의를 연결한다. 공개 Sites와 미디어 서버의 운영 배포는 하지 않았다.
